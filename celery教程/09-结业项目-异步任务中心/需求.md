# 09 · 结业项目:异步任务中心(需求书)

把常用语法拼成一个"云上小店"商户后台:导出报表(CPU)、发邮件(IO)、定时任务(Beat)。不用 Canvas、不用数据库;验收看终端日志和 `/tmp/shop-reports/` 里的文件。

## 1 任务清单

文件怎么拆归你。路由集中在 `task_routes`,队列三条:`shop.compute`、`shop.io`、`shop.default`(兜底)。

| 任务 | 队列 | 要求 |
|---|---|---|
| `shop.export_report` | compute | 真计算约 3 秒(纯 Python 循环聚合,别 sleep),写 CSV 到 `/tmp/shop-reports/`;算完在任务体内 `delay` 发通知邮件,并 `apply_async(countdown=30, expires=60)` 安排删文件(参数可关,见剧本) |
| `shop.send_email` | io | 发信写死 1 秒;收件以 `.invalid` 结尾必失败;带 `autoretry_for=(临时异常,)`、`retry_backoff=2`、`max_retries=2` |
| `shop.delete_file` | io | 删指定文件;文件已不在就安静返回 |
| `shop.sweep_reports` | io | Beat 每 15 秒调一次:删掉"最后修改超过 60 秒"的旧文件 |
| `shop.daily_report` | compute | Beat 每分钟调一次(生产改 `crontab(minute=5, hour=0)`):全平台聚合约 3 秒,`delay` 发运营通知 |

## 2 启动(项目目录内,三个终端)

```bash
uv run celery -A app worker -l INFO -n cpu@%h -P prefork -c 2 -Q shop.compute,shop.default --prefetch-multiplier=1
uv run celery -A app worker -l INFO -n io@%h -P threads -c 4 -Q shop.io --prefetch-multiplier=8
uv run celery -A app beat -l INFO
```

cpu 是 prefork + prefetch=1(计算要公平);io 是 threads + prefetch=8(等网络的短任务多囤点);timezone 统一 `Asia/Shanghai`;Beat 只准起一个。

## 3 剧本(提交端写死)

| 时刻 | 动作 |
|---|---|
| t=0 | 公告邮件 `delay`;导出 M01 |
| t=1 | 导出 M02(传参关掉"安排删文件",专等巡检来收) |
| t=3 | 导出 M04(邮箱 `m04@shop.invalid`,通知必败) |
| 之后 | 静静看 90 秒 |

## 4 验收

1. 公告 ≈1 秒发出(io worker),此刻 compute 还有活在算——两条队列互不耽误;
2. 三张 CSV 先后出现;M01 在完成后约 30 秒被删(countdown),M02 活到 60 秒才被巡检删——两条清理路分得清;
3. M04 通知三次尝试同一个 task_id,间隔约 2 秒、4 秒,之后放弃;
4. Beat 每 15 秒发巡检、每个整分钟发日报,日报由 cpu 聚合后发运营通知;
5. `uv run celery -A app status` 两个节点在线;`inspect active_queues` 各听各的队列。

选做:compute 队列声明 `x-max-priority=10`,连投几张普通单后 `apply_async(priority=9)` 投一张 VIP,看它反超;计算中 `kill -9` cpu worker 再重启,看 acks_late 重投。
