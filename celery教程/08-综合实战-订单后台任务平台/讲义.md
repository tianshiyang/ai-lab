# 第 8 讲 · 综合实战:订单后台任务平台

七讲的零件合成一套电商后台:下单扣库存、超时自动关单、付款通知、失败重试与告警、定时对账。业务还是那家云上小店——和兔 MQ 教程第 8 讲**同一家店,两个版本的实现**,这一讲从头到尾都在做对照。

## 0 架构

```
 order_api.py(下单/模拟付款)                        beat(每分钟)
   │ 下单:扣库存 + 20 秒关单倒计时                      │ reconcile 对账
   ▼                                                   ▼
 ┌─ 路由表 ──────────────────────────────────────────────────────┐
 │  tasks.orders.* ──► shop.orders 队列 ──► worker A(-Q shop.orders)
 │  tasks.notify.* ──► shop.notify 队列 ──► worker B(-Q shop.notify)
 │  漏写路由的 ─────► shop.default ──► 没人吃,管理台监控(第 4 讲的兜底)
 └───────────────────────────────────────────────────────────────┘
 付款事件:send_sms(失败 autoretry 2 次,耗尽 → FAILURE → 告警任务)
          grant_points(数据库标记幂等)
```

三笔订单的剧本(写死在 `order_api.py`),和兔 MQ 第 8 讲同款:

| 订单 | 剧本 | 预期结局 |
|---|---|---|
| A3001 | 5 秒后付款,一切正常 | 库存扣、短信发、积分到账;20 秒到点查单已付款,不取消 |
| A3002 | 不付款 | 20 秒后自动取消、释放库存 |
| A3003 | 8 秒后付款,短信网关必挂 | 短信重试三次全败 → FAILURE → 告警任务喊人;积分照发 |

**两个版本的同题对照**(这一讲最重要的阅读方式):

| 零件 | 兔 MQ 版(第 8 讲) | Celery 版(本讲) |
|---|---|---|
| 超时关单 | 建等待队列挂 `x-message-ttl` + DLX 改路由键 + 回查服务,四个部件 | `cancel_if_unpaid.apply_async(countdown=20)`,一行 |
| 短信重试 | 手写"ack 旧的、投带 retry 计数的新消息" | `autoretry_for + retry_backoff`,两个装饰器参数 |
| 重试耗尽 | `nack(requeue=False)` → 死信队列 → watcher | FAILURE + `on_failure` 基类 → 告警任务 |
| 分流消费 | 每个服务一个脚本,各自 set_qos、订阅 | 路由表 + 两个 worker 命令 |
| 幂等 | 订单表标记 / 内存 set | 订单表标记(一模一样) |

兔 MQ 版把**传输层**的每个零件亲手拼了一遍,你从此知道框架底下在发生什么;Celery 版是**框架层**的写法,同样的可靠语义,代码量一折——两套都过手,面试聊到任何一个都能从 broker 讲到业务。

## 2 celery_app.py

```python
"""第 8 讲·Celery 应用:全套企业配置,两个域两条队列加一条兜底。"""

import os
from pathlib import Path

from celery import Celery
from celery.schedules import crontab
from dotenv import load_dotenv
from kombu import Exchange, Queue

load_dotenv(Path(__file__).parents[2] / ".env")

app = Celery(
    "shop",
    broker=os.environ["RABBITMQ_URL"],
    backend=os.environ["REDIS_URL"],
    include=["tasks.orders", "tasks.notify"],
)

exchange = Exchange("shop", type="direct")

app.conf.update(
    # —— 序列化与时间 ——
    task_serializer="json",
    result_serializer="json",
    accept_content=["json"],
    timezone="Asia/Shanghai",
    # —— 可靠性三件套(第 3 讲)——
    task_acks_late=True,
    task_reject_on_worker_lost=True,
    worker_prefetch_multiplier=1,
    result_expires=3600,
    # —— 全局兜底(第 7 讲)——
    task_time_limit=60,
    worker_max_tasks_per_child=1000,
    # —— 队列与路由(第 4 讲)——
    task_queues=(
        Queue("shop.default", exchange, routing_key="shop.default"),
        Queue("shop.orders", exchange, routing_key="shop.orders"),
        Queue("shop.notify", exchange, routing_key="shop.notify"),
    ),
    task_default_queue="shop.default",           # 兜底:漏写路由的任务落这里,worker 不吃
    task_create_missing_queues=False,
    task_routes={                                   # 一个 dict:key 是任务名或通配
        "tasks.orders.*": {"queue": "shop.orders"},
        "tasks.notify.*": {"queue": "shop.notify"},
    },
    # —— 周期调度(第 5 讲)——
    beat_schedule={
        "订单对账": {
            "task": "tasks.orders.reconcile",
            "schedule": crontab(minute="*"),
        },
    },
)
```

## 3 db.py

和兔 MQ 版同一个思路:json 假装 MySQL,**每个写操作都自带幂等标记**。

```python
"""第 8 讲·极简订单表:一个 json 文件假装是数据库,写操作自带幂等标记。"""

import json
from pathlib import Path

DB_FILE = Path(__file__).parent / "orders.json"


def load() -> dict:
    if not DB_FILE.exists():
        return {}
    return json.loads(DB_FILE.read_text(encoding="utf-8"))


def save(orders: dict) -> None:
    DB_FILE.write_text(json.dumps(orders, ensure_ascii=False, indent=2), encoding="utf-8")


def get(order_id: str) -> dict | None:
    return load().get(order_id)


def create(order_id: str, amount: int, sms_will_fail: bool = False) -> None:
    orders = load()
    orders[order_id] = {
        "order_id": order_id,
        "amount": amount,
        "status": "待付款",
        "stock_deducted": False,     # 扣库存的幂等标记
        "points_granted": False,     # 积分的幂等标记
        "sms_sent": False,           # 短信的幂等标记
        "sms_will_fail": sms_will_fail,
    }
    save(orders)


def mark_paid(order_id: str) -> None:
    orders = load()
    orders[order_id]["status"] = "已付款"
    save(orders)


def deduct_stock(order_id: str) -> bool:
    """扣库存,已扣过返回 False —— 幂等"""
    orders = load()
    if order_id not in orders or orders[order_id]["stock_deducted"]:
        return False
    orders[order_id]["stock_deducted"] = True
    save(orders)
    return True


def grant_points(order_id: str) -> bool:
    """发积分,已发过返回 False —— 幂等"""
    orders = load()
    if order_id not in orders or orders[order_id]["points_granted"]:
        return False
    orders[order_id]["points_granted"] = True
    save(orders)
    return True


def mark_sms_sent(order_id: str) -> bool:
    orders = load()
    if order_id not in orders or orders[order_id]["sms_sent"]:
        return False
    orders[order_id]["sms_sent"] = True
    save(orders)
    return True


def cancel(order_id: str, reason: str) -> None:
    orders = load()
    orders[order_id]["status"] = "已取消"
    orders[order_id]["cancel_reason"] = reason
    save(orders)
```

## 4 tasks/orders.py

```python
"""第 8 讲·订单域任务:路由表送它们进 shop.orders。"""

import time

from celery.utils.log import get_task_logger

import db
from celery_app import app

logger = get_task_logger(__name__)


@app.task
def deduct_stock(order_id: str) -> None:
    """下单即扣库存。标记防重:任务被重投/重试,库存只扣一次"""
    time.sleep(0.5)   # 假装在调库存服务
    if db.deduct_stock(order_id):
        logger.info("订单 %s 库存已扣", order_id)
    else:
        logger.info("订单 %s 库存已扣过,跳过(幂等)", order_id)


@app.task
def cancel_if_unpaid(order_id: str) -> None:
    """20 秒关单倒计时到点:回查业务状态,没付款才取消(第 6 讲的老规矩)"""
    order = db.get(order_id)
    if order is None:
        logger.warning("订单 %s 不存在,丢弃", order_id)
        return
    if order["status"] == "已付款":
        logger.info("订单 %s 到点但已付款,不处理", order_id)
    elif order["status"] == "已取消":
        logger.info("订单 %s 已取消过,跳过(幂等)", order_id)
    else:
        db.cancel(order_id, "超时未付款")
        logger.info("订单 %s 20 秒未付款 → 取消,释放库存", order_id)


@app.task(ignore_result=True)
def reconcile() -> None:
    """对账(beat 每分钟):扫一遍订单表,打印全景。真实项目里:找超时未处理的、金额对不上的"""
    orders = db.load()
    logger.info("【对账】共 %s 笔:%s", len(orders),
                ", ".join(f"{o['order_id']}({o['status']})" for o in orders.values()))
```

## 5 tasks/notify.py

```python
"""第 8 讲·通知域任务:路由表送它们进 shop.notify。短信自带重试与告警。"""

from celery import Task
from celery.utils.log import get_task_logger

import db
from celery_app import app

logger = get_task_logger(__name__)


class AlertOnFailure(Task):
    """失败告警基类(第 3 讲):重试耗尽 → 自动派告警任务"""

    def on_failure(self, exc, task_id, args, kwargs, einfo):
        alert_devops.delay(task_name=self.name, task_id=task_id,
                           payload=str(args), error=str(exc))


class SmsGatewayError(Exception):
    """短信网关故障:值得重试的那种错"""


@app.task(base=AlertOnFailure, bind=True,
          autoretry_for=(SmsGatewayError,), retry_backoff=True, retry_jitter=True,
          max_retries=2, ignore_result=True)
def send_sms(self, order_id: str) -> None:
    """支付成功短信:剧本订单三连败 → 重试耗尽 → 告警"""
    order = db.get(order_id)
    if order is None:
        logger.warning("订单 %s 不存在,丢弃", order_id)
        return
    if order["sms_sent"]:
        logger.info("订单 %s 短信已发过,跳过(幂等)", order_id)
        return
    if order["sms_will_fail"]:
        raise SmsGatewayError(f"短信网关 503(第 {self.request.retries + 1} 次)")
    db.mark_sms_sent(order_id)
    logger.info("短信:【云上小店】订单 %s 已支付 %s 元", order_id, order["amount"])


@app.task(ignore_result=True)
def grant_points(order_id: str) -> None:
    """按金额发积分,表标记幂等:先落库,干别的事在后"""
    order = db.get(order_id)
    if order and db.grant_points(order_id):
        logger.info("积分:订单 %s 发放 %s 分", order_id, order["amount"])
    else:
        logger.info("积分:订单 %s 已发过或不存在,跳过", order_id)


@app.task(ignore_result=True)
def alert_devops(task_name: str, task_id: str, payload: str, error: str) -> None:
    """告警落地:生产上换成钉钉/飞书机器人"""
    logger.warning("【告警】%s[%s] 重试耗尽,需人工处理 | 参数 %s | 错误 %s",
                   task_name, task_id, payload, error)
```

## 6 order_api.py

三个动作:下单(扣库存 + 埋 20 秒关单倒计时)、模拟付款(改库后发通知)、走人。

```python
"""第 8 讲·订单入口:下单、埋关单倒计时、模拟付款触发通知。

    cd "celery教程/08-综合实战-订单后台任务平台"
    uv run python order_api.py
"""

import time

import db
from tasks.notify import grant_points, send_sms
from tasks.orders import cancel_if_unpaid, deduct_stock

# (订单号, 金额, 短信会不会失败, 会不会付款)
ORDERS = [
    ("A3001", 199, False, True),
    ("A3002", 59, False, False),
    ("A3003", 299, True, True),
]


def now() -> str:
    return f"[{time.strftime('%H:%M:%S')}]"


def place(order_id: str, amount: int, sms_will_fail: bool) -> None:
    db.create(order_id, amount, sms_will_fail)
    deduct_stock.delay(order_id)                                   # 下单即扣库存
    cancel_if_unpaid.apply_async(args=[order_id], countdown=20)    # 20 秒关单倒计时
    print(f"{now()} 下单:{order_id},{amount} 元,20 秒付款窗口开始")


def pay(order_id: str) -> None:
    db.mark_paid(order_id)          # 先改库
    send_sms.delay(order_id)        # 再发通知(顺序反了,下游查库还是"待付款")
    grant_points.delay(order_id)
    print(f"{now()} 付款:{order_id} → 通知两件套已投递")


def main() -> None:
    for order_id, amount, sms_will_fail, _will_pay in ORDERS:
        place(order_id, amount, sms_will_fail)
    print(f"{now()} 剧情设定:5 秒后 A3001 付款,8 秒后 A3003 付款,A3002 不付")
    time.sleep(5)
    pay("A3001")
    time.sleep(3)
    pay("A3003")
    print(f"{now()} 入口退场,后台继续;对账任务每分钟整分跑一次,最多等一分钟")


main()
```

## 7 跑起来

四个终端,`order_api.py` 最后跑:

```
终端 1:  cd "celery教程/08-综合实战-订单后台任务平台"
         uv run celery -A celery_app worker --pool=solo -l info -Q shop.orders -n orders@%h
终端 2:  uv run celery -A celery_app worker --pool=solo -l info -Q shop.notify -n notify@%h
终端 3:  uv run celery -A celery_app beat -l info
终端 4:  uv run python order_api.py
```

四个终端按时间对齐(1/2 是两个 worker,行尾标了是谁):

```
[20:04:11] 下单:A3001 / A3002 / A3003,20 秒付款窗口开始
[20:04:11] (orders) 订单 A3001/A3002/A3003 库存已扣
[20:04:16] 付款:A3001 → 通知两件套已投递
[20:04:16] (notify)  短信:【云上小店】订单 A3001 已支付 199 元
[20:04:16] (notify)  积分:订单 A3001 发放 199 分
[20:04:19] 付款:A3003 → 通知两件套已投递
[20:04:19] (notify)  积分:订单 A3003 发放 299 分
[20:04:19] (notify)  短信网关 503(第 1 次)→ Retry in 0s
[20:04:19] (notify)  短信网关 503(第 2 次)→ Retry in 1s
[20:04:21] (notify)  短信网关 503(第 3 次)→ FAILURE
[20:04:21] (notify)  【告警】tasks.notify.send_sms[...] 重试耗尽,需人工处理 | 参数 ['A3003'] | 错误 短信网关 503(第 3 次)
[20:04:31] (orders)  订单 A3001 到点但已付款,不处理
[20:04:31] (orders)  订单 A3002 20 秒未付款 → 取消,释放库存
[20:04:31] (orders)  订单 A3003 到点但已付款,不处理
[20:05:00] (orders)  【对账】共 3 笔:A3001(已付款), A3002(已取消), A3003(已付款)
```

重试间隔每次都不一样:`retry_jitter` 把指数退避打散成 `[0, 2^n)` 的随机数(第 3 讲),别指望固定的 1s/2s——三次尝试挤在同一秒里也正常。

验收:打开 `orders.json`——

| 订单 | 终局 |
|---|---|
| A3001 | 已付款;库存已扣、积分已发、短信已发 |
| A3002 | 已取消(超时未付款);库存已扣(取消时口头释放) |
| A3003 | 已付款;积分已发;`sms_sent: false` —— 短信只存在于告警里,等人工补偿 |

## 9 对应到真实系统

| 本讲 | 企业里的名字 |
|---|---|
| order_api.py 的 `place/pay` | 订单服务的接口层,`.delay()` 写在事务提交后 |
| shop.orders / shop.notify 队列 | 按域拆的 worker 组,各自扩容、各自的池(第 7 讲) |
| `cancel_if_unpaid(countdown=20)` | 订单超时关闭(电商标配 30 分钟,生产用 RabbitMQ 时注意过期消息别堆队头) |
| AlertOnFailure → alert_devops | 告警中心(钉钉/飞书机器人 + 值班群),重放靠管理台/任务表 |
| reconcile | 财务对账/卡单扫描,夜间批处理的门面 |
| orders.json | MySQL 的 orders 表,幂等标记是表上的字段或唯一键 |
