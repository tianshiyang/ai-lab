# 第 4 讲 · 多队列与任务路由

## 0 开场:为什么要分队列

全教程到第 3 讲只用一条队列。一个团队、几十种任务挤一条队列,迟早撞上三件事:

| 痛 | 场景 | 分队列之后 |
|---|---|---|
| 慢任务海啸 | 视频转码挤满队列,密码重置邮件排队 20 分钟 | 邮件任务走自己的队列,海啸淹不到 |
| 资源特征打架 | IO 型任务(调接口)和 CPU 型任务(转码)想要的并发池完全不同 | 各队列各配各的 worker 和池 |
| 扩容没抓手 | "加机器"加给谁? | 按队列扩:邮件堵了加邮件 worker |

```
                     ┌─ 路由表:tasks.mail.* ──► c4.mail 队列 ──► worker A(-Q c4.mail)
 调用端 ──► exchange ─┼─ 路由表:tasks.media.* ─► c4.media 队列 ─► worker B(-Q c4.media)
                     └─ 没配上路由的 ─────────► c4.default ──► 没人吃,堆在管理台里一眼可见
```

队列还是兔 MQ 第 2 讲那条队列,只是从"一条大通铺"改成"按业务域分房间"。**路由靠任务名**:所以第 1 讲说任务名是全局坐标——`tasks.mail.*` 这样的域名规划,现在开始收利息。

## 1 显式声明队列

```python
from kombu import Exchange, Queue

app.conf.update(
    task_queues=(
        Queue("c4.default", Exchange("cel4", type="direct"), routing_key="c4.default"),
        Queue("c4.mail", Exchange("cel4", type="direct"), routing_key="c4.mail"),
        Queue("c4.media", Exchange("cel4", type="direct"), routing_key="c4.media"),
    ),
    task_default_queue="c4.default",   # 兜底队列:漏写路由的任务的去处
    task_create_missing_queues=False,
)
```

| 配置 | 说明 |
|---|---|
| `Queue(名字, 交换机, routing_key=)` | 名字、durable 等参数一次性写全,worker 启动时自动声明(不需要你去管理台建) |
| `Exchange("cel4", type="direct")` | 多条队列共用一个 direct 交换机,靠 routing_key 区分——兔 MQ 第 3 讲 direct 的标准用法 |
| `task_default_queue="c4.default"` | 漏写路由的任务的去处。**这条队列必须在 task_queues 里声明**,且 worker 故意不吃它(下面敲黑板) |
| `task_create_missing_queues=False` | **企业必开**。默认 True 时,路由到 task_queues 之外的队列会"贴心地"现建一条——拼错队列名的任务从此石沉大海,谁也不知道 |

**敲黑板:防呆是两层的。** ①`task_create_missing_queues=False` 管住"拼错"——路由到没声明的队列,投递当场 `KeyError`,不会默默建孤儿队列。②显式默认队列管住"漏写"——没配上路由的任务落在 `c4.default`,而 worker 的 `-Q` 只给业务队列:兜底队列没人吃,堆积在管理台一眼可见,报警去查,而不是混进业务队列捣乱。(顺带一提:不声明默认队列也躲不掉——`task_queues` 里没有 `task_default_queue` 指的那条时,**所有任务**第一次投递就 `KeyError`,实测踩过。)

## 2 路由表 task_routes

```python
app.conf.update(
    task_routes={                                   # 注意:是一个 dict,不是元组列表
        "tasks.mail.*": {"queue": "c4.mail"},       # key 可以是通配:mail 域全部
        "tasks.media.*": {"queue": "c4.media"},
    },
)
```

| 写法 | 匹配 | 用途 |
|---|---|---|
| `{"tasks.mail.send_email": {"queue": "c4.mail"}}` | 任务名精确匹配 | 个别特调 |
| `{"tasks.mail.*": {"queue": "c4.mail"}}` | key 带通配 | **主力**:按域整建制路由 |
| 函数 `def route(name, args, kwargs, options, **kw): return {"queue": ...}` | 运行时计算 | 极少用,如"按参数分片" |

路由表里除了 `queue`,还能塞 `exchange` / `routing_key` / `priority`——同一种"调运选项",装饰器、路由表、apply_async 三处都能给,合并生效。

路由表**是代码**(版本控制、review、随服务发布);`-Q` 是**部署**(同一份代码,不同机器吃不同队列)。两不混淆。

## 3 工程结构:任务按域拆包

第 1 讲的单文件 `tasks.py` 升级成包——这是 Celery 工程长到几十个任务后的标准形态(Django 项目里就是各 app 的 `tasks.py`,autodiscover 自动找):

```
04-多队列与任务路由/
├── celery_app.py
├── send.py
└── tasks/
    ├── __init__.py     # 空文件,声明这是个包
    ├── mail.py         # 邮件域:任务名自带 tasks.mail. 前缀
    └── media.py        # 媒体域:tasks.media. 前缀
```

```python
app = Celery("cel4", ..., include=["tasks.mail", "tasks.media"])
```

任务名跟着模块走:`tasks/mail.py` 里的 `send_email` 就叫 `tasks.mail.send_email`——域名是模块路径送你的,路由表直接按 `tasks.mail.*` 收编。**先规划任务名,再写路由表**,顺序别反。

## 4 启动专用 worker

```
终端 1:  uv run celery -A celery_app worker --pool=solo -l info -Q c4.mail -n mail@%h
终端 2:  uv run celery -A celery_app worker --pool=solo -l info -Q c4.media -n media@%h
```

| 段 | 作用 |
|---|---|
| `-Q c4.mail` | 只守 c4.mail 一条队列 |
| `-Q c4.mail,c4.media` | 两条都守(通吃型 worker) |
| `-n mail@%h` | 给 worker 起名(日志、监控、远程命令都按名找人);`%h` 展开为主机名 |

worker 横幅的 `[queues]` 段只列自己守的队列——**部署有没有配错,看横幅一眼便知**;`inspect registered`(第 7 讲)能远程点名。

## 5 优先级:脸熟

兔 MQ 第 7 讲的优先级队列,Celery 侧只差"把参数带进去"两头:

```python
Queue("c4.mail", exchange, routing_key="c4.mail",
      queue_arguments={"x-max-priority": 10}),   # ① 队列开优先级(broker 侧)

send_email.apply_async(args=..., priority=9)      # ② 消息声明优先级(调用侧)
```

两头都设置才生效,和兔 MQ 教程速查里的"两头清单"同一条规矩。数字越大越先跑,默认 5。加急邮件插队就这么干,不展开。

## 6 完整示例

### celery_app.py

```python
"""第 4 讲·Celery 应用:多队列 + 路由表。"""

import os
from pathlib import Path

from celery import Celery
from dotenv import load_dotenv
from kombu import Exchange, Queue

load_dotenv(Path(__file__).parents[2] / ".env")

app = Celery(
    "cel4",
    broker=os.environ["RABBITMQ_URL"],
    backend=os.environ["REDIS_URL"],
    include=["tasks.mail", "tasks.media"],
)

exchange = Exchange("cel4", type="direct")   # 两队列共用一个 direct 交换机

app.conf.update(
    task_serializer="json",
    result_serializer="json",
    accept_content=["json"],
    timezone="Asia/Shanghai",
    task_acks_late=True,
    task_reject_on_worker_lost=True,
    worker_prefetch_multiplier=1,
    result_expires=3600,
    # —— 本讲主角:显式队列 + 默认兜底 + 防呆 + 路由表 ——
    task_queues=(
        Queue("c4.default", exchange, routing_key="c4.default"),
        Queue("c4.mail", exchange, routing_key="c4.mail",
              queue_arguments={"x-max-priority": 10}),
        Queue("c4.media", exchange, routing_key="c4.media"),
    ),
    task_default_queue="c4.default",          # 漏写路由的任务落这里,没人吃、盯着它
    task_create_missing_queues=False,          # 拼错队列名 → 投递当场报错
    task_routes={                              # dict:key 是任务名或通配
        "tasks.mail.*": {"queue": "c4.mail"},
        "tasks.media.*": {"queue": "c4.media"},
    },
)
```

### tasks/__init__.py

```python
# 空文件:让 tasks/ 成为包。域内任务写在 mail.py / media.py。
```

### tasks/mail.py

```python
"""第 4 讲·邮件域任务:任务名自带 tasks.mail. 前缀,整域路由到 c4.mail。"""

import time

from celery.utils.log import get_task_logger

from celery_app import app

logger = get_task_logger(__name__)


@app.task(ignore_result=True)
def send_email(to: str, subject: str) -> None:
    """发邮件:IO 型,睡 2 秒假装调 SMTP"""
    logger.info("给 %s 发邮件:%s", to, subject)
    time.sleep(2)
    logger.info("邮件已发出:%s", to)
```

### tasks/media.py

```python
"""第 4 讲·媒体域任务:CPU 重活,路由到 c4.media,和邮件互不干扰。"""

import time

from celery.utils.log import get_task_logger

from celery_app import app

logger = get_task_logger(__name__)


@app.task
def transcode_video(video_id: int, seconds: int = 8) -> dict:
    """转码:重活,睡 seconds 秒假装 CPU 拉满"""
    logger.info("视频 %s 开始转码,要 %s 秒", video_id, seconds)
    time.sleep(seconds)
    return {"video_id": video_id, "resolution": "1080p"}
```

### send.py

```python
"""第 4 讲·调用端:邮件(轻)和转码(重)各投各的,看两个 worker 各干各的。

    cd "celery教程/04-多队列与任务路由"
    uv run python send.py
"""

import time

from tasks.mail import send_email
from tasks.media import transcode_video

def now() -> str:
    return time.strftime("%H:%M:%S")

for i in range(1, 3):
    send_email.delay(to=f"user{i}@shop.com", subject=f"订单确认 {i}")
    print(f"[{now()}] 邮件 {i} 已投递 → c4.mail")

for video_id in (101, 102):
    r = transcode_video.delay(video_id, seconds=8)
    print(f"[{now()}] 转码 {video_id} 已投递 → c4.media(ID: {r.id[:8]}…)")
```

send.py 里没写一个队列名——**路由表在 app 里,调用端根本不需要知道队列存在**。这就是路由表集中管理的红利:运维调整队列布局,调用端代码一行不动。

## 7 跑起来

**实验一:两个 worker 各守各队。** 开两个终端分别跑第 4 节两条命令(注意横幅 `[queues]` 各只列自己那条),然后:

```
终端 3:  uv run python send.py
```

```
[19:02:10] 邮件 1 已投递 → c4.mail
[19:02:10] 邮件 2 已投递 → c4.mail
[19:02:10] 转码 101 已投递 → c4.media(ID: 4b1d…)
[19:02:10] 转码 102 已投递 → c4.media(ID: 77a0…)
```

mail worker 的终端:两封邮件 2 秒一封,4 秒干完收工;media worker 的终端:两个转码 8 秒一个,磨到 16 秒。**两边的时间线互不等待**——搁第 3 讲的单队列里,邮件得排在转码后面干瞪眼 16 秒。

**实验二:爆炸半径隔离。** Ctrl+C 停掉 media worker,只留 mail worker,把 send.py 里的编号改大重跑(或再跑一遍):邮件照常 4 秒发完,管理台 `c4.media` 队列 Ready 数稳稳挂 2——**转码任务的故障(没 worker)完全没碰邮件**。再把 media worker 开起来,看它把堆积两口吃掉。队列隔离的真正卖点不是"快",是**一个域出事,别的域无感**。

**实验三(顺手):通吃 worker。** 单个终端 `-Q c4.mail,c4.media` 起一个 worker,重跑 send.py——一个进程两条队列全守,开发机上这么跑很方便;生产上才按域分开。

## 8 速查表

| API / 配置 | 层 | 作用 |
|---|---|---|
| `Queue(名, Exchange, routing_key=, queue_arguments=)` | app.conf | 显式声明队列 |
| `task_create_missing_queues=False` | app.conf | 防呆:拼错队列名当场报错 |
| `task_default_queue="c4.default"` | app.conf | 漏写路由任务的兜底队列(worker 不吃,管理台监控) |
| `task_routes={"tasks.mail.*": {"queue": ...}}` | app.conf | 路由表(一个 dict),key 按任务名通配 |
| `include=["tasks.mail", ...]` | Celery(...) | 任务模块清单 |
| `-Q c4.mail` / `-Q a,b` | 命令行 | worker 守哪条(部署决定) |
| `-n 名字@%h` | 命令行 | worker 起名 |
| `queue_arguments={"x-max-priority": 10}` + `priority=N` | 队列 + apply_async | 优先级,两头都设才生效 |
