# 第 1 讲 · 收发第一条消息

## 0 模型

```
                 ┌──────────────── broker(服务器上的 RabbitMQ)────────────────┐
  生产者 send.py │   交换机(本讲用自带的默认交换机)      ch1.hello 队列         │  消费者 receive.py
  ───发消息───►  │  ──────────────────────────────────►  [msg][msg][msg]  ─────┼──► 取走后 ack
                 └──────────────────────────────────────────────────────────┘
```

生产者不认识消费者,只管把消息投进队列;消息在队列里排队,谁订阅谁取走。后面七讲全是在这个模型上加零件。

| 概念 | 一句话 |
|---|---|
| 连接 Connection | 到 broker 的 TCP 连接,建立成本高 |
| 信道 Channel | 连接里的逻辑通道,所有操作都发生在信道上,廉价,可开多条 |
| 交换机 Exchange | 收消息、按规则分发给队列(第 3 讲) |
| 队列 Queue | 存消息的地方,消息在这里排队等消费 |
| 生产者 / 消费者 | 发消息的 / 收消息的,互不知道对方存在 |

## 1 连接地址与 vhost

```
amqp://用户名:密码@主机:端口/vhost
```

**vhost**:broker 内部的隔离舱,队列和交换机都关在 vhost 里,互相不可见。本教程用专建的 `lab`,和业务用的 vhost 互不干扰。

| 要点 | 说明 |
|---|---|
| 默认 vhost 叫 `/` | 写进 URL 必须转义成 `%2F`,否则连错地方;`lab` 无此问题 |
| `?heartbeat=30` | URL 可挂参数,心跳秒数,防止防火墙掐掉长闲连接;学习阶段用默认 |

地址带密码,仓库公开,所以放在仓库根目录的 `.env`(已被 .gitignore 排除),脚本里读:

```python
load_dotenv(Path(__file__).parents[2] / ".env")   # parents[2] = 从脚本往上跳两级到仓库根
RABBITMQ_URL = os.environ["RABBITMQ_URL"]
```

这四行是后面每一讲脚本的固定开头。

## 2 建连接与开信道

```python
connection = await aio_pika.connect(RABBITMQ_URL)
async with connection:                 # 出块自动关闭,中途抛异常也不会漏关
    channel = await connection.channel()
```

| API | 说明 |
|---|---|
| `aio_pika.connect(url)` | 建立 TCP 连接,握手 + 鉴权 |
| `connection.channel()` | 在连接上开一条信道,发收消息、声明队列都在信道上做 |

- **一个连接开多条信道**是标准用法:TCP 连接贵,信道便宜,各信道的操作互不干扰
- aio-pika 里**所有方法都是协程**,漏写 `await` 不报错,只是拿到一个没跑过的协程对象,下一行才炸

---

## 3 声明队列

**是什么**:`declare_queue` = 不存在就建,已存在就拿到引用。

**解决什么**:幂等声明,生产者和消费者各声明一次都合法,**没有启动顺序要求**。

```python
queue = await channel.declare_queue("ch1.hello", durable=True)
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `name` | 随机名 | 队列名 |
| `durable` | `False` | 队列定义落盘,broker 重启后仍在(第 4 讲) |

- 同名队列**重复声明时参数必须完全一致**,否则 broker 报 406 并关闭信道(第 4 讲 §4)。改了脚本里的队列参数而老队列还在,就会撞上它,去管理台删掉旧队列重跑

---

## 4 发消息

**默认交换机**:broker 自带,名字是空字符串。规则:**路由键写哪个队列名,消息就直投哪个队列**,不需要任何绑定。

```python
await channel.default_exchange.publish(
    aio_pika.Message("你好".encode()),   # body 必须是 bytes
    routing_key=queue.name,              # 队列名当路由键
)
```

| 要点 | 说明 |
|---|---|
| `Message(body)` | body 必须是 `bytes`,传 str 直接报错;所以有 `.encode()` / 收方 `.decode()` |
| 真实业务写法 | `json.dumps(业务字典).encode()`,收方 `json.loads`(第 2 讲起都这么写) |
| publisher confirm | aio-pika 信道默认开着,`await publish(...)` 返回即代表 broker 已收到(第 4 讲) |

---

## 5 收消息与 ack

```python
async for message in queue.iterator():   # 订阅:broker 推一条,循环走一轮
    print(message.body.decode())
    await message.ack()                  # 确认:broker 这时才真正删除
```

| 写法 | 说明 |
|---|---|
| `queue.iterator()` | 迭代器式订阅,本教程统一用它,好读 |
| `queue.consume(回调)` | 回调式订阅,等价 |
| `queue.get()` | 主动拉一条,一次性场景用(第 3 讲) |

- 消息投递给消费者后**并没有删除**,只是标记"已投递未确认";`ack()` 之后 broker 才删
- 消费者拿到消息、没 ack 就崩了 → broker 重新投递,消息不丢(第 2 讲整章实验)
- `ack()` 也是协程,别漏 `await`

## 6 完整示例

仓库里不提供 `.py`,照着敲到本目录,文件名按下面的写(命令按名字找文件)。

### send.py

```python
"""第 1 讲·发送端:往 ch1.hello 队列里放三条消息。

在仓库根目录(ai-lab)下执行:
    uv run python "rabbitmq教程/01-收发第一条消息/send.py"
"""

import asyncio
import os
from pathlib import Path

import aio_pika
from dotenv import load_dotenv

# 从仓库根目录的 .env 读连接地址(仓库是公开的,密码不能写进代码)
load_dotenv(Path(__file__).parents[2] / ".env")
RABBITMQ_URL = os.environ["RABBITMQ_URL"]


async def main() -> None:
    connection = await aio_pika.connect(RABBITMQ_URL)
    async with connection:
        channel = await connection.channel()
        queue = await channel.declare_queue("ch1.hello", durable=True)

        messages = [
            "你好,RabbitMQ",
            "第二条:一张外卖订单",
            "第三条:一条短信验证码",
        ]
        for text in messages:
            await channel.default_exchange.publish(
                aio_pika.Message(text.encode()),
                routing_key=queue.name,
            )
            print(f"已发送: {text}")

    print("发完了。管理台 Queues 页的 ch1.hello 里躺着 3 条消息")
    print("管理台地址: http://62.234.16.180:15672(账号密码同 .env 里的 RABBITMQ_URL)")


asyncio.run(main())
```

### receive.py

```python
"""第 1 讲·接收端:守着 ch1.hello 队列,来一条收一条,收到第 3 条后退出。

    uv run python "rabbitmq教程/01-收发第一条消息/receive.py"
"""

import asyncio
import os
from pathlib import Path

import aio_pika
from dotenv import load_dotenv

load_dotenv(Path(__file__).parents[2] / ".env")
RABBITMQ_URL = os.environ["RABBITMQ_URL"]


async def main() -> None:
    connection = await aio_pika.connect(RABBITMQ_URL)
    async with connection:
        channel = await connection.channel()
        # 和 send.py 一字不差地再声明一次:声明幂等,已存在就只是拿到引用
        queue = await channel.declare_queue("ch1.hello", durable=True)

        print("接收端已启动,等消息进来……")
        received = 0
        async for message in queue.iterator():
            text = message.body.decode()
            received += 1
            print(f"收到第 {received} 条: {text}")
            await message.ack()

            if received == 3:
                break

    print("全部收到,连接关闭,进程退出")


asyncio.run(main())
```

## 7 跑起来

两个终端,顺序无所谓(先开 receive.py 等着,现象更直观):

```
uv run python "rabbitmq教程/01-收发第一条消息/send.py"
uv run python "rabbitmq教程/01-收发第一条消息/receive.py"
```

```
已发送: 你好,RabbitMQ
已发送: 第二条:一张外卖订单
已发送: 第三条:一条短信验证码

接收端已启动,等消息进来……
收到第 1 条: 你好,RabbitMQ
收到第 2 条: 第二条:一张外卖订单
收到第 3 条: 第三条:一条短信验证码
```

**值得做的实验**:只跑 `send.py`,不启动接收端,去管理台 Queues 页看 `ch1.hello` —— Features 列有 `D`,消息数 3。把 receive.py 跑起来又 Ctrl+C 掐掉,隔十分钟再跑,消息一条不少。**队列是能长期存东西的仓库,不是流水的管子**。

看完到管理台把 `ch1.hello` 删掉(点进队列,拉到底 Delete Queue)。

## 8 速查表

| API / 参数 | 位置 | 作用 |
|---|---|---|
| `aio_pika.connect(url)` | — | 建连接 |
| `connection.channel()` | 连接 | 开信道 |
