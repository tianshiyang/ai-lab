# 第 3 讲 · 三种交换机

## 0 交换机与绑定

前两讲消息都直进队列,靠的是默认交换机"路由键=队列名"的特殊照顾。真实的消息架构里,中间站着**交换机**:

```
                                    ch3.orders(topic 交换机)
   订单服务 ──publish──►  ( 消息 + 路由键 )──►  按绑定规则分发  ──┬──► 队列A  绑定键 order.created
                                                                 ├──► 队列B  绑定键 order.*
                                                                 └──► 队列C  绑定键 #
```

| 概念 | 一句话 |
|---|---|
| 交换机 Exchange | 收生产者的消息,按类型和绑定关系决定投给哪些队列 |
| 绑定 Binding | 一条登记规则:"队列 A 想要路由键长这样的消息"。永远是队列绑向交换机 |

**生产者只跟交换机打交道**,消息进哪个队列由交换机类型和绑定关系决定。生产者不知道也不该知道有哪些队列——新增一个订阅方(比如数据分析想听订单事件),它自己声明队列、自己绑定就行,上游一行不改。这就是 MQ"解耦"的落点。

企业里 90% 的路由需求就是这三种:

| 类型 | 路由规则 | 典型场景 |
|---|---|---|
| fanout | 无视路由键,广播给所有绑定的队列 | 配置刷新、日志多路分发 |
| direct | 路由键与绑定键**完全相等**才投 | 固定通道指派:短信走短信、邮件走邮件 |
| topic | 绑定键可带通配符 `*` `#` | 事件总线,企业主力 |

---

## 1 fanout:广播

**是什么**:绑到这个交换机上的队列,每条消息都收到一份完整副本,路由键形同虚设。

```
                         ch3.logs(fanout:不看路由键,绑了就给)
    生产者 ──发 1 条──►   ──┬──► 副本① ──► ch3.log.archive(归档库)
                            └──► 副本② ──► ch3.log.console(实时大屏)

    发 3 条 → 两个队列各收 3 条,共 6 份拷贝,内容一模一样
```

```python
exchange = await channel.declare_exchange(
    "ch3.logs", aio_pika.ExchangeType.FANOUT, durable=True
)
archive = await channel.declare_queue("ch3.log.archive", durable=True)
await archive.bind(exchange, routing_key="")   # fanout 不看路由键,空串即可
await exchange.publish(aio_pika.Message(log.encode()), routing_key="")
```

一条"配置变更了"的消息,同时让归档库和实时大屏都收到,就是它。

---

## 2 direct:定向

**是什么**:消息的路由键和绑定键完全相等,才投给那个队列。

```
                          ch3.notify(direct:路由键 == 绑定键,全等才投)
    生产者 ──路由键 sms ────►  ✓ ──► ch3.sms(绑 sms)     → 收下
           ──路由键 email ───►  ✓ ──► ch3.email(绑 email) → 收下
           ──路由键 push ─────►  没有队列绑 push           → 直接丢弃
```

```python
sms = await channel.declare_queue("ch3.sms", durable=True)
await sms.bind(exchange, routing_key="sms")     # 短信队列只认 sms
await exchange.publish(msg, routing_key="sms")  # 只有它收到
```

- 一条消息能匹配多个绑定就投多份(比如两个队列都绑了 `sms`)
- 路由不到任何队列的消息**直接丢弃,生产端毫无知觉**——想感知它要开 mandatory,第 4 讲 §6
- 第 1 讲的默认交换机就是个 direct 交换机,只是 broker 预先把每个队列用"自己的队列名"绑好了

## 3 topic:通配符,企业主力

**是什么**:路由键和绑定键都按 `.` 分词,绑定键里可用两个通配符。

| 通配符 | 匹配 | 例 |
|---|---|---|
| `*` | 恰好**一个**词 | `order.*` 配 `order.paid`,不配 `order` 也不配 `order.paid.timeout` |
| `#` | **零个或多个**词 | `order.#` 配 `order`、`order.paid`、`order.paid.timeout`;单独 `#` 来者不拒 |

```python
await q1.bind(exchange, routing_key="order.created")  # 精确:只盯新订单
await q2.bind(exchange, routing_key="order.*")        # 订单的所有单步动作
await q3.bind(exchange, routing_key="#")              # 全站所有事件
```

示例拓扑:4 条事件撞上 3 个绑定键,谁收到谁(✓=投进该队列):

```
   事件 \ 绑定键        order.created   order.*    #
   ───────────────────────────────────────────────
   order.created             ✓            ✓       ✓
   order.paid                ✗            ✓       ✓
   order.cancelled           ✗            ✓       ✓
   refund.created            ✗            ✗       ✓
   ───────────────────────────────────────────────
   到手条数                  1            3       4
```

拿不准就用 topic:绑 `#` 退化为 fanout,绑精确键退化为 direct,路由键按 `业务域.动作` 分层,以后怎么变都有余地。

还有第四种 headers 交换机(按消息头键值对匹配),几乎没人用,知道存在即可。

## 4 declare_exchange 与 bind

```python
exchange = await channel.declare_exchange("ch3.orders", aio_pika.ExchangeType.TOPIC, durable=True)
await queue.bind(exchange, routing_key="order.created")
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `type` | direct | fanout / direct / topic / headers,路由行为的全部 |
| `durable` | False | 交换机定义落盘,生产恒开 |
| `auto_delete` | False | 最后一个绑定解除后自动删,少用 |
| `internal` | False | 只许 broker 内部转发,基本不用 |

- 声明幂等,参数必须与已存在的一致,否则 406 关信道——规矩和队列一样(第 4 讲 §4)
- 一个队列可以绑**多个**绑定键(一次登记多种口味);一个交换机可以挂任意多队列

---

## 5 queue.get():拉模式

前两讲消费都是订阅(iterator),broker 主动推。`queue.get()` 是反过来主动拉一条:

```python
message = await queue.get(no_ack=True, fail=False, timeout=2)   # 队列空返回 None
```

| 参数 | 说明 |
|---|---|
| `fail=False` | 队列空返回 None;默认 True 会抛 QueueEmpty |
| 适用 | 轮询、巡检、脚本结尾"把结果倒出来看看"这类一次性场景 |

常驻消费者永远用订阅:拉的实时性差,空轮询浪费。

## 6 完整示例

三个脚本结构相同:声明交换机 → 声明队列并绑定 → 发消息 → 各队列倒出来看 → 删掉演示资源。仓库里不提供 `.py`,照着敲到本目录。

### fanout.py

```python
"""第 3 讲·fanout 交换机:广播——绑了它的队列,每条都收一份副本。

    uv run python "rabbitmq教程/03-三种交换机/fanout.py"
"""

import asyncio
import os
from pathlib import Path

import aio_pika
from dotenv import load_dotenv

load_dotenv(Path(__file__).parents[2] / ".env")
RABBITMQ_URL = os.environ["RABBITMQ_URL"]

LOGS = [
    "[WARN] 库存服务响应变慢",
    "[INFO] 用户 1001 登录成功",
    "[ERROR] 支付回调第三次重试",
]


async def drain(queue: aio_pika.Queue) -> list[str]:
    """把队列里现成的消息全部取出来(取走即确认,演示够用)"""
    messages = []
    while True:
        message = await queue.get(no_ack=True, fail=False, timeout=2)
        if message is None:
            return messages
        messages.append(message.body.decode("utf-8"))


async def main() -> None:
    connection = await aio_pika.connect(RABBITMQ_URL)
    async with connection:
        channel = await connection.channel()

        exchange = await channel.declare_exchange(
            "ch3.logs", aio_pika.ExchangeType.FANOUT, durable=True
        )

        # 两个订阅者:归档 + 实时上屏。fanout 不看路由键,绑定时空串即可
        archive = await channel.declare_queue("ch3.log.archive", durable=True)
        console = await channel.declare_queue("ch3.log.console", durable=True)
        await archive.purge()
        await console.purge()
        await archive.bind(exchange, routing_key="")
        await console.bind(exchange, routing_key="")

        for log in LOGS:
            await exchange.publish(aio_pika.Message(log.encode("utf-8")), routing_key="")
            print(f"已广播: {log}")

        print("\n广播完毕,看看两个订阅者各自收到了什么:")
        for name, queue in [("归档库", archive), ("控制台", console)]:
            received = await drain(queue)
            print(f"\n[{name}] 收到 {len(received)} 条(和发出的一模一样):")
            for text in received:
                print(f"    {text}")

        await archive.delete()
        await console.delete()
        await exchange.delete()


asyncio.run(main())
```

### direct.py

```python
"""第 3 讲·direct 交换机:定向——路由键完全相等,才投给谁。

    uv run python "rabbitmq教程/03-三种交换机/direct.py"
"""

import asyncio
import os
from pathlib import Path

import aio_pika
from dotenv import load_dotenv

load_dotenv(Path(__file__).parents[2] / ".env")
RABBITMQ_URL = os.environ["RABBITMQ_URL"]

# (路由键, 消息内容):一条消息该走哪个通道,由路由键说了算
NOTIFICATIONS = [
    ("sms", "验证码 8848,五分钟内有效"),
    ("email", "您本月的账单已出,附件为明细"),
    ("sms", "您的快递已到丰巢,取件码 3306"),
    ("push", "这条走 push 通道——但没人绑定 push,它会被直接丢弃"),
]


async def drain(queue: aio_pika.Queue) -> list[str]:
    messages = []
    while True:
        message = await queue.get(no_ack=True, fail=False, timeout=2)
        if message is None:
            return messages
        messages.append(message.body.decode("utf-8"))


async def main() -> None:
    connection = await aio_pika.connect(RABBITMQ_URL)
    async with connection:
        channel = await connection.channel()

        exchange = await channel.declare_exchange(
            "ch3.notify", aio_pika.ExchangeType.DIRECT, durable=True
        )

        # 短信队列只绑 "sms",邮件队列只绑 "email"。没有队列绑 "push"
        sms = await channel.declare_queue("ch3.sms", durable=True)
        email = await channel.declare_queue("ch3.email", durable=True)
        await sms.purge()
        await email.purge()
        await sms.bind(exchange, routing_key="sms")
        await email.bind(exchange, routing_key="email")

        for routing_key, text in NOTIFICATIONS:
            await exchange.publish(
                aio_pika.Message(text.encode("utf-8")), routing_key=routing_key
            )
            print(f"已发送 → 路由键[{routing_key}]: {text}")

        print("\n投递完毕,看看谁收到了什么:")
        for name, queue in [("短信队列", sms), ("邮件队列", email)]:
            received = await drain(queue)
            print(f"\n[{name}] 收到 {len(received)} 条:")
            for text in received:
                print(f"    {text}")

        print("\n走 push 的那条,两边都没收到——路由不到任何队列的消息,direct 直接丢弃")
        print("(怎么感知路由失败?第 4 讲的 mandatory 讲这个)")

        await sms.delete()
        await email.delete()
        await exchange.delete()


asyncio.run(main())
```

### topic.py

```python
"""第 3 讲·topic 交换机:通配符——路由键按点分词,* 配一个词,# 配零个或多个词。

    uv run python "rabbitmq教程/03-三种交换机/topic.py"
"""

import asyncio
import os
from pathlib import Path

import aio_pika
from dotenv import load_dotenv

load_dotenv(Path(__file__).parents[2] / ".env")
RABBITMQ_URL = os.environ["RABBITMQ_URL"]

# (路由键, 消息内容)
EVENTS = [
    ("order.created", "订单 A1001 创建"),
    ("order.paid", "订单 A1001 支付成功"),
    ("order.cancelled", "订单 B2002 取消"),
    ("refund.created", "退款单 R3003 创建"),
]


async def drain(queue: aio_pika.Queue) -> list[str]:
    messages = []
    while True:
        message = await queue.get(no_ack=True, fail=False, timeout=2)
        if message is None:
            return messages
        messages.append(message.body.decode("utf-8"))


async def main() -> None:
    connection = await aio_pika.connect(RABBITMQ_URL)
    async with connection:
        channel = await connection.channel()

        exchange = await channel.declare_exchange(
            "ch3.orders", aio_pika.ExchangeType.TOPIC, durable=True
        )

        # 三个订阅者,口味一个比一个广
        watch_created = await channel.declare_queue("ch3.watch.created", durable=True)
        watch_orders = await channel.declare_queue("ch3.watch.orders", durable=True)
        watch_all = await channel.declare_queue("ch3.watch.all", durable=True)
        for q in (watch_created, watch_orders, watch_all):
            await q.purge()

        await watch_created.bind(exchange, routing_key="order.created")  # 精确匹配
        await watch_orders.bind(exchange, routing_key="order.*")        # order.一个词
        await watch_all.bind(exchange, routing_key="#")                 # 来者不拒

        for routing_key, text in EVENTS:
            await exchange.publish(
                aio_pika.Message(text.encode("utf-8")), routing_key=routing_key
            )
            print(f"已发送 → [{routing_key}]: {text}")

        print("\n投递完毕,三个订阅者各自收到了:")
        for name, queue in [
            ("只盯下单 order.created", watch_created),
            ("订单动作 order.*", watch_orders),
            ("全站事件 #", watch_all),
        ]:
            received = await drain(queue)
            print(f"\n[{name}] 收到 {len(received)} 条:")
            for text in received:
                print(f"    {text}")

        await watch_created.delete()
        await watch_orders.delete()
        await watch_all.delete()
        await exchange.delete()


asyncio.run(main())
```

## 8 怎么选

| 场景 | 选型 |
|---|---|
| 事件通知、多方订阅、未来可能加订阅方 | **topic**,路由键按 `业务域.动作` 分层 |
| 一对一指派、固定通道 | direct |
| 无差别广播(配置刷新、缓存失效) | fanout |

## 9 速查表

| API / 参数 | 位置 | 作用 |
|---|---|---|
| `ExchangeType.FANOUT` | `declare_exchange` | 广播,无视路由键 |
| `ExchangeType.DIRECT` | `declare_exchange` | 路由键完全相等才投 |
| `ExchangeType.TOPIC` | `declare_exchange` | 通配符:`*` 一个词,`#` 零个或多个 |
| `queue.bind(exchange, routing_key=...)` | 队列 | 登记:队列想要路由键长这样的消息 |
| `queue.get(no_ack=True, fail=False)` | 队列 | 拉一条,一次性场景用 |
