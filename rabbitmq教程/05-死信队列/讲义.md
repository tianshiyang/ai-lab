# 第 5 讲 · 死信队列

## 0 死信是什么

消息在队列里"死掉"后,broker 把它转投到另一个交换机,而不是丢弃。这个机制叫死信(Dead Letter)。

```
  业务队列(声明时配了 x-dead-letter-exchange)
        │ 消息死亡 → broker 自动转投,并在消息头写入 x-death 档案
        ▼
  死信交换机(普通交换机)──► 死信队列(普通队列)──► 告警 / 人工排查 / 修复后重放
```

**死信队列不是一种新的队列类型**,就是"普通交换机 + 普通队列 + 业务队列上的一个参数"。

三种死因:

| reason | 触发条件 | 本讲 |
|---|---|---|
| `rejected` | 消费者 `nack(requeue=False)` 或 `reject(requeue=False)` | §2 |
| `expired` | 消息 TTL 到期 | 第 6 讲 |
| `maxlen` | 队列达到 `x-max-length`,消息被挤出 | §4 |

---

## 1 x-dead-letter-exchange

**是什么**:队列的一个 argument,指定这个队列里死掉的消息转投到哪个交换机。

**解决什么**:没配它,死掉的消息直接消失,连尸首都没有。

```python
dlx = await channel.declare_exchange("ch5.dlx", aio_pika.ExchangeType.FANOUT, durable=True)
dead = await channel.declare_queue("ch5.dead", durable=True)
await dead.bind(dlx)                       # 死信交换机和死信队列,都是普通货色

orders = await channel.declare_queue(
    "ch5.orders",
    durable=True,
    arguments={"x-dead-letter-exchange": "ch5.dlx"},   # ← 魔法只有这一行
)
```

| argument | 值 | 作用 |
|---|---|---|
| `x-dead-letter-exchange` | 交换机名 | 死信转投的目标交换机 |
| `x-dead-letter-routing-key` | 路由键 | 转投时改写路由键;不配则沿用消息原来的路由键 |

- 转投是 **broker 内部的异步动作**,nack 返回后立刻去死信队列取,可能扑空
- 一个 DLX 挂多个出口时用 direct + `x-dead-letter-routing-key` 分流(第 6 讲、第 8 讲用到)

---

## 2 nack 与 reject

**是什么**:消费者拒绝一条消息的两个 API。

**解决什么**:告诉 broker "这条我处理不了",由 `requeue` 决定它是回队列重试还是去死。

```python
await message.nack(requeue=False)    # 处死 → 走 DLX
await message.nack(requeue=True)     # 塞回队列立刻重投
```

| | `nack()` | `reject()` |
|---|---|---|
| `requeue` 默认值 | **True**(塞回队列) | **False**(处死) |
| 批量 | 支持 `multiple=True` | 不支持,一次一条 |

- 两个默认值相反,**永远显式写出 requeue**
- `requeue=True` 遇到"谁来谁失败"的毒消息 = 无限重投死循环
- 队列没配 DLX 时 `requeue=False` = 消息直接蒸发

配对关系:

| 队列配了 DLX | 消费端写法 | 结果 |
|:---:|---|---|
| ✓ | `nack(requeue=False)` | 进死信队列 ✔ |
| ✓ | `nack()`(默认 requeue=True) | 原地打转,永远到不了死信 |
| ✗ | `nack(requeue=False)` | 消息蒸发 |

---

## 3 x-max-length 与 x-overflow

**是什么**:限制队列最大长度,以及满了之后怎么办。

**解决什么**:防止队列无限堆积撑爆 broker;被挤出的消息配合 DLX 还能留档。

```python
vip = await channel.declare_queue(
    "ch5.vip",
    durable=True,
    arguments={
        "x-max-length": 2,                       # 最多攒 2 条
        "x-dead-letter-exchange": "ch5.dlx",     # 挤出去的不丢,进死信
    },
)
```

| argument | 值 | 行为 |
|---|---|---|
| `x-max-length` | 条数 | 队列最大消息数 |
| `x-max-length-bytes` | 字节数 | 按体积限制 |
| `x-overflow` | `drop-head`(默认) | 挤掉**最老的**,老消息变死信 |
| | `reject-publish` | 拒收**新的**,生产端在 publisher confirm 里收到 nack |

- 保新丢旧 → `drop-head`;保旧拒新 → `reject-publish`
- 被挤出不等于丢弃:配了 DLX 就进死信队列

---

## 4 x-death 档案

**是什么**:消息转投死信时,broker 自动写进消息头的一份死亡记录。

**解决什么**:死信队列里躺着一条消息时,你能知道它从哪来、为什么死、死过几次。

```python
for death in message.headers.get("x-death", []):
    print(death["reason"], death["queue"], death["count"])
```

真实内容:

```python
{'x-death': [{'count': 1, 'reason': 'rejected', 'queue': 'ch5.orders',
              'time': datetime(2026, 9, 16, 9, 53, 5, tzinfo=utc),
              'exchange': '', 'routing-keys': ['ch5.orders']}],
 'x-first-death-exchange': '', 'x-first-death-queue': 'ch5.orders',
 'x-first-death-reason': 'rejected'}
```

| 字段 | 含义 |
|---|---|
| `reason` | 死因:rejected / expired / maxlen |
| `queue` | 死在哪个队列 |
| `count` | 在这个队列死过几次 —— **做死信重放时的阈值依据** |
| `time` | 死亡时间 |
| `routing-keys` | 原路由键 |
| `x-first-death-*` | 第一次死亡的交换机 / 队列 / 原因 |

- `x-death` 是个**列表**:消息死过多轮(重放又死)时每轮一条,能还原整个流转史
- 字段值偶尔以 `bytes` 传来,取用前统一 decode

---

## 5 死信队列怎么消费

死信队列是普通队列,消费方式没有任何特殊。两种常规做法:

| 做法 | 说明 |
|---|---|
| 挂监控消费者 | 死信一到就把消息体 + x-death 推给告警机器人,转人工。第 8 讲的 `watcher.py` |
| 不消费,定时导出 | 让死信堆着,每天定时任务导出人工排查,修复后重投回业务队列 |

---

## 6 完整示例:两种死因各一个脚本

rejected 和 maxlen 是两种独立的死法,各写各的、各讲各的;真实项目里 DLX 也是各业务队列配各的,没有把两种死因拼在一个脚本里的写法——全套拼装(死信 + 延迟 + 重试)在第 8 讲。

### dead_reject.py —— 死因 rejected(§2)

```python
"""第 5 讲·死因一 rejected:消费者 nack(requeue=False),broker 把消息转投死信。

    uv run python "rabbitmq教程/05-死信队列/dead_reject.py"
"""

import asyncio
import os
from pathlib import Path

import aio_pika
from dotenv import load_dotenv

load_dotenv(Path(__file__).parents[2] / ".env")
RABBITMQ_URL = os.environ["RABBITMQ_URL"]


def decode(value: object) -> object:
    """x-death 字段偶尔是 bytes,统一转成可读值"""
    return value.decode("utf-8") if isinstance(value, bytes) else value


async def main() -> None:
    connection = await aio_pika.connect(RABBITMQ_URL)
    async with connection:
        channel = await connection.channel()

        # 死信交换机 + 死信队列:都是普通的
        dlx = await channel.declare_exchange(
            "ch5.dlx", aio_pika.ExchangeType.FANOUT, durable=True
        )
        dead = await channel.declare_queue("ch5.dead", durable=True)
        await dead.bind(dlx)
        await dead.purge()

        # 业务队列:唯一特殊的就是 x-dead-letter-exchange 这一行
        orders = await channel.declare_queue(
            "ch5.orders",
            durable=True,
            arguments={"x-dead-letter-exchange": "ch5.dlx"},
        )
        await orders.purge()

        for body in [
            "正常订单-A",
            "正常订单-B",
            "毒订单-X(内容非法,谁来谁失败)",
        ]:
            await channel.default_exchange.publish(
                aio_pika.Message(body.encode("utf-8")), routing_key=orders.name
            )

        print("三条消息,前两条 ack,第三条 nack(requeue=False)")
        for _ in range(3):
            message = await orders.get()
            body = message.body.decode("utf-8")
            if "毒" in body:
                print(f"  处理失败,处死: {body}")
                await message.nack(requeue=False)
            else:
                print(f"  处理成功: {body}")
                await message.ack()

        await asyncio.sleep(0.5)   # 转投是 broker 的异步动作,留出时间
        print("\n死信队列里躺着它,带着档案:")
        while True:
            message = await dead.get(no_ack=True, fail=False, timeout=2)
            if message is None:
                break
            print(f"  收到死信: {message.body.decode('utf-8')}")
            for death in message.headers.get("x-death", []):
                print(
                    f"    档案: 原因={decode(death.get('reason'))}  "
                    f"原队列={decode(death.get('queue'))}  "
                    f"次数={decode(death.get('count'))}  "
                    f"时间={decode(death.get('time'))}"
                )

        await orders.delete()
        await dead.delete()
        await dlx.delete()


asyncio.run(main())
```

### dead_maxlen.py —— 死因 maxlen(§3)

```python
"""第 5 讲·死因二 maxlen:x-max-length=2 的队列塞 4 条,最老的 2 条被挤进死信。

    uv run python "rabbitmq教程/05-死信队列/dead_maxlen.py"
"""

import asyncio
import os
from pathlib import Path

import aio_pika
from dotenv import load_dotenv

load_dotenv(Path(__file__).parents[2] / ".env")
RABBITMQ_URL = os.environ["RABBITMQ_URL"]


def decode(value: object) -> object:
    """x-death 字段偶尔是 bytes,统一转成可读值"""
    return value.decode("utf-8") if isinstance(value, bytes) else value


async def main() -> None:
    connection = await aio_pika.connect(RABBITMQ_URL)
    async with connection:
        channel = await connection.channel()

        dlx = await channel.declare_exchange(
            "ch5.dlx", aio_pika.ExchangeType.FANOUT, durable=True
        )
        dead = await channel.declare_queue("ch5.dead", durable=True)
        await dead.bind(dlx)
        await dead.purge()

        vip = await channel.declare_queue(
            "ch5.vip",
            durable=True,
            arguments={
                "x-max-length": 2,                       # 最多攒 2 条
                "x-dead-letter-exchange": "ch5.dlx",     # 挤出去的不丢,进死信
            },
        )
        await vip.purge()

        for i in range(1, 5):
            await channel.default_exchange.publish(
                aio_pika.Message(f"VIP 消息-{i}".encode()), routing_key=vip.name
            )
        print("x-max-length=2 的队列,塞进 4 条消息")

        await asyncio.sleep(0.3)
        remain = []
        while True:
            message = await vip.get(no_ack=True, fail=False, timeout=2)
            if message is None:
                break
            remain.append(message.body.decode("utf-8"))
        print(f"  队列里剩下: {remain}")

        print("\n被挤掉的 2 条老消息进了死信队列,带着档案:")
        while True:
            message = await dead.get(no_ack=True, fail=False, timeout=2)
            if message is None:
                break
            print(f"  收到死信: {message.body.decode('utf-8')}")
            for death in message.headers.get("x-death", []):
                print(
                    f"    档案: 原因={decode(death.get('reason'))}  "
                    f"原队列={decode(death.get('queue'))}  "
                    f"次数={decode(death.get('count'))}"
                )

        await vip.delete()
        await dead.delete()
        await dlx.delete()


asyncio.run(main())
```

```
uv run python "rabbitmq教程/05-死信队列/dead_reject.py"
uv run python "rabbitmq教程/05-死信队列/dead_maxlen.py"
```

实跑输出(档案里的时间是 broker 的 UTC 时间,比北京时间慢 8 小时)。`dead_reject.py`:

```
三条消息,前两条 ack,第三条 nack(requeue=False)
  处理成功: 正常订单-A
  处理成功: 正常订单-B
  处理失败,处死: 毒订单-X(内容非法,谁来谁失败)

死信队列里躺着它,带着档案:
  收到死信: 毒订单-X(内容非法,谁来谁失败)
    档案: 原因=rejected  原队列=ch5.orders  次数=1  时间=2026-09-18 03:28:16+00:00
```

`dead_maxlen.py`——队列里留下最新的,最老的 2 条去了死信:

```
x-max-length=2 的队列,塞进 4 条消息
  队列里剩下: ['VIP 消息-3', 'VIP 消息-4']

被挤掉的 2 条老消息进了死信队列,带着档案:
  收到死信: VIP 消息-1
    档案: 原因=maxlen  原队列=ch5.vip  次数=1
  收到死信: VIP 消息-2
    档案: 原因=maxlen  原队列=ch5.vip  次数=1
```

两个容易踩的点:

| 现象 | 原因 |
|---|---|
| nack 后立刻查死信队列是空的 | 转投是异步的,示例用 `sleep(0.5)` 等一下 |
| `queue.get()` 取不到还没发生的消息 | get 是"当场看一眼",要蹲守未来的消息用 `iterator()` / `consume()` |

## 8 速查表

| 配置 / API | 写在哪 | 默认 | 作用 |
|---|---|---|---|
| `x-dead-letter-exchange` | 队列 arguments | 无 | 死信转投目标 |
| `x-dead-letter-routing-key` | 队列 arguments | 沿用原路由键 | 转投时改写路由键 |
| `x-max-length` | 队列 arguments | 无限 | 队列最大条数 |
| `x-overflow` | 队列 arguments | `drop-head` | 满了挤老的 / `reject-publish` 拒新的 |
| `nack(requeue=?)` | 消费端 | True | False 才进死信 |
| `reject(requeue=?)` | 消费端 | False | 一次一条 |
| `x-death` | 消息 headers | — | 死因 / 原队列 / 次数 / 时间 |

下一讲:`expired` 这种死因能拿来做定时 —— TTL + 死信 = 延迟队列。
