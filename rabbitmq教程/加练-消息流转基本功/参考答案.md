## 0 对象清单(就这六个)

| 名字 | 是什么 | 关键参数 |
|---|---|---|
| `e1` | topic 交换机 | durable |
| `d1` | direct 交换机(死信用) | durable |
| `q1` | 工作队列,worker 消费它 | durable;**DLX=d1,改写键=dead** |
| `q2` | 观察队列,看所有广播 | durable;绑 e1 / `task.*` |
| `q3` | 重试中转队列,**无人消费** | durable;**TTL=5000 毫秒;DLX=默认交换机,改写键=q1** |
| `q4` | 死信池 | durable;绑 d1 / `dead` |

## 1 接线总表(每一条"消息怎么走")

| # | 从 | 到 | 走哪里 | 什么时候 |
|---|---|---|---|---|
| 1 | 生产者 | q1 | publish 到 **e1**,键=`task.run`(q1 的精确绑定接住) | 发新任务,永远 |
| 2 | 生产者 | q2 | 同一条消息,再走一遍 e1 的 `task.*` 通配绑定 | 同上——一投两到 |
| 3 | worker | q2 | publish 到 **e1**,键=`task.done` | 处理成功后广播 |
| 4 | worker | q3 | **默认交换机直投**,键=q3 队列名,`headers={"retry": n+1}` | 处理失败且 retry<2 |
| 5 | q3 | q1 | 躺满 5 秒 → **expired 死信** → q3 的 DLX(默认交换机)→ 改写键=q1 → 直落 q1 | 自动,broker 干的 |
| 6 | q1 | q4 | `nack(requeue=False)` → **rejected 死信** → q1 的 DLX(d1)→ 改写键=dead → d1 的绑定接住 | 处理失败且 retry≥2 |

## 2 流转图

```
producer ──publish(e1, "task.run")──►  e1(topic)
                                        │
              ┌─────────────────────────┤
              │ q1 绑 task.run          │ q2 绑 task.*
              ▼                         ▼
             q1 ──► worker             q2 ──► observer(打印每条的键和内容)
                      │
     ┌────────────────┼──────────────────────┐
     │ 成功            │ 失败,retry<2          │ 失败,retry≥2
     ▼                ▼                      ▼
 publish(e1,"task.done")  直投 q3          nack(requeue=False)
     │                │                      │
     ▼                │                      ▼
    q2 收到           │(见下方回路)        q1 的 DLX=d1,改写键 dead
                                    d1 ──绑定 dead──► q4 ──► watcher

【重试回路】
 worker 失败 ──直投(headers retry+1)──► q3(x-message-ttl=5000,无人消费)
                                          │ 躺满 5 秒 → expired 死信
                                          ▼
                        DLX=默认交换机,改写键=q1 → 直落回 q1
                                          │
                                          ▼
                            worker 再领:header 里的 retry 还在(死信转发保留属性)
```

## 3 规则逐条(消费者收到消息后干什么)

**worker(消费 q1)**,每条消息按顺序判断:

1. 解 body:`{"id": "T2", "fail": true}`;解 header:`retry`(没有就是 0)
2. `fail=false` → 打印"T1 处理成功" → publish(e1, 键 `task.done`, body 原样)→ **ack**
3. `fail=true` 且 `retry<2` → 打印"T2 失败,第 {retry+1} 次,5 秒后重试" → 默认交换机直投 q3(**原 body 原样带走,headers={"retry": retry+1}**)→ **ack 旧的**
4. `fail=true` 且 `retry≥2` → 打印"T2 三连败,放弃" → **nack(requeue=False)**——之后的事全是 broker 的:q1 死信改键 dead → d1 → q4

**observer(消费 q2)**:打印每条消息的路由键 + body,ack。

**watcher(消费 q4)**:打印消息体 + x-death 全部档案,ack。

## 4 剧本与预期

producer 发 T1(`fail=false`)和 T2(`fail=true`):

- T1 一次成功;T2 三次被 worker 处理,相邻开始时间各隔约 5 秒
- observer 恰好 3 条:`task.run`×2 + `task.done`×1(重试直投,不走广播)
- watcher 收到 1 条死信,档案两条:expired(q3)count=2、rejected(q1)count=1
- 跑完全部队列 Ready=0
