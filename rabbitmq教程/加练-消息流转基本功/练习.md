# 加练 · 消息流转系统(照图实现)

一张总图拆成**三张分图**:事件广播、重试回路、死信出口。编号 ①~⑨ 连续,逐跳说明在图后面。所有队列/交换机的**属性**用行为语言写在属性表里——翻译成 `arguments` 是你的活。

一条消息的一生,一句话:**任务从 e1 广播出去,worker 干;干砸了去 q3 睡 5 秒回来再干;干砸三次,进 q4 等人看。**

## 图一 · 事件广播(正常流)

```
              ① 发任务(key=task.run,body 带 fail 标记)
 producer ─────────────────────────────────►  e1(topic 交换机)
                                               │② q1 绑 task.run(只收任务,精确)
                                               │③ q2 绑 task.*(什么事件都看,通配)
                    ┌──────────────────────────┴─────────────┐
                    ▼②                                       ▼③
              q1(工作队列)                              q2(观察队列)
                    │④ worker 消费                             │ observer 消费:
                    ▼                                          ▼ 打印每条的键+内容
                 worker ──⑤ 成功:广播(key=task.done)──►  e1(再走③落进 q2)
```

## 图二 · 重试回路(失败但还有救)

```
 worker ──⑥ 失败且次数<3:直投(默认交换机,key=q3 队列名,
        header 次数+1,body 原样)──►  q3(等待队列:所有消息统一活 5 秒,无人消费)
                                          │⑦ 躺满 5 秒,expired 死信
                                          ▼
                       死信改键"q1" ──► 默认交换机 ──► 直落 q1,worker 再领
                       (body 和 header 原样都在,次数记得住)
```

## 图三 · 死信出口(三次全败,放弃)

```
 worker ──⑧ 第 3 次失败:nack(requeue=False)──►  q1 的死信机制:改键"dead" ──►  d1(direct 交换机)
                                                                                 │⑨ q4 绑"dead"
                                                                                 ▼
                                                                           q4(死信池)
                                                                                 │ watcher 消费
                                                                                 ▼
                                                   打印消息体 + x-death 档案(死因/经过的队列/各几次)
```

## 逐跳说明

| # | 谁干的 | 从→到 | 键 | 说明 |
|---|---|---|---|---|
| ① | producer | → e1 | `task.run` | 每条任务发一次;body:`{"id": "T1", "fail": false}` |
| ② | 绑定 | e1 → q1 | `task.run` | 精确键:只有"任务"能进工作队列,⑤的完成事件进不来 |
| ③ | 绑定 | e1 → q2 | `task.*` | 通配键:两个词、task 开头的事件全收——所以①和⑤它都看得见 |
| ④ | worker | 消费 q1 | — | 读 body 的 fail、读 header 的次数,往下走⑥/⑤/⑧三个分支之一 |
| ⑤ | worker | → e1 | `task.done` | 成功才广播,body 原样带走;随后 ack |
| ⑥ | worker | → q3 | **q3 的队列名** | 直投走默认交换机(键=队列名=地址);新消息 headers 次数+1;**投完 ack 旧消息** |
| ⑦ | broker | q3 → q1 | **q1 的队列名** | 到期死信自动改键、自动投默认交换机,直落 q1——这条全程没人写代码,broker 照 q3 的属性办事 |
| ⑧ | worker | q1 → d1 | —(由 q1 属性改写为 `dead`) | 全系统唯一一次 `nack`;nack 之前先把"放弃"打印出来 |
| ⑨ | 绑定 | d1 → q4 | `dead` | 和⑧改写出的键配对,死信落池 |

**默认交换机出场两次**:⑥(worker 主动直投 q3)、⑦(死信自动回流 q1)——两次的键都是"目标队列的名字"。

## 对象属性表(把行为翻成 arguments,你来)

| 对象 | 必须具备的性质(行为语言) |
|---|---|
| e1 | topic 类型;键是"两词、task 开头"的事件名 |
| q1 | 工作队列;消息被 nack 放弃时,改键 `dead` 投给 d1 |
| q2 | 观察队列;绑 e1 / `task.*` |
| q3 | **无人消费**;里面所有消息统一活 5 秒;到期后改键 `q1` 投给**默认交换机** |
| d1 | direct 类型;一个出口就够 |
| q4 | 死信池;绑 d1 / `dead` |

## 剧本与验收

producer 写死两条:T1(fail=false)、T2(fail=true)。

1. T2 三次被 worker 处理,相邻**开始时间**各隔约 5 秒;
2. observer 恰好打印 3 条:task.run×2 + task.done×1,别无其他(重试、死信都不走 e1);
3. watcher 收到 1 条,档案两条:expired(原队列 q3)count=2、rejected(原队列 q1)count=1;
4. 跑完全部队列 Ready=0;
5. 杀进程实验:T2 躺 q3 期间 `Ctrl+C` 掉 worker,重启后消息照样被处理,终局不变。
