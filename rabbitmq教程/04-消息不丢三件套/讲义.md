# 第 4 讲 · 可靠投递

消息从生产者到消费者走三段路,每段有各自的丢失原因和解法:

| 路段 | 丢失原因 | 解法 | 所在讲 |
|---|---|---|---|
| ① 生产者 → broker | 网络断、交换机路由不到任何队列 | publisher confirm + mandatory | 本讲 §5 §6 |
| ② broker 内存 → 磁盘 | broker 重启,内存里的东西全没 | 队列 durable + 消息 PERSISTENT | 本讲 §1 §2 |
| ③ broker → 消费者 | 消费者收到后崩溃 | 手动 ack | 第 2 讲 |

本讲补齐①②。

---

## 1 队列持久化 durable

**是什么**:`durable=True` 把**队列的定义**(名字、绑定、参数)写入磁盘。

**解决什么**:broker 重启后队列还在。非持久化队列重启即消失,里面的消息一并消失。

```python
queue = await channel.declare_queue("ch4.persist", durable=True)
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `durable` | `False` | aio-pika 的默认值是 False,生产代码必须显式写 True |

- 管理台 Queues 页 Features 列显示 `D` 即为持久化
- **只管队列本身,不管消息** —— 见 §2

---

## 2 消息持久化 delivery_mode

**是什么**:`delivery_mode=PERSISTENT` 把**这一条消息**写入磁盘。

**解决什么**:消息不再只躺在内存,broker 重启后仍在队列里。

```python
await channel.default_exchange.publish(
    aio_pika.Message(body, delivery_mode=aio_pika.DeliveryMode.PERSISTENT),
    routing_key="ch4.persist",
)
```

| 值 | 数值 | 含义 | 默认 |
|---|---|---|---|
| `DeliveryMode.NOT_PERSISTENT` | 1 | 只在内存 | ✓ |
| `DeliveryMode.PERSISTENT` | 2 | 写盘 | |

- 不是发一条刷一次盘,broker 攒批写。极端断电仍可能丢最后零点几秒
- 要更强保证用 quorum 队列(第 7 讲)

---

## 3 两个开关的四种组合

| 队列 durable | 消息 PERSISTENT | broker 重启后 |
|:---:|:---:|---|
| ✗ | ✗ | 队列没了,消息没了 |
| ✗ | ✓ | 队列没了,消息陪葬 |
| ✓ | ✗ | 队列在,消息没了 |
| ✓ | ✓ | **都在** |

只拧一边等于没拧。生产代码两个一起上。

---

## 4 声明冲突 406

同名队列用不同参数重复声明,broker 拒绝:

```python
await channel.declare_queue("ch4.persist", durable=True)   # 第一次,建成功
await channel.declare_queue("ch4.persist", durable=False)  # 第二次,参数不一致 → 报错
```

```
ChannelPreconditionFailed: PRECONDITION_FAILED - inequivalent arg 'durable'
for queue 'ch4.persist': received 'false' but current is 'true'
```

| 现象 | 原因 | 解法 |
|---|---|---|
| 406 PRECONDITION_FAILED | broker 上的老队列参数与代码里的不一致 | 管理台删掉老队列,让新参数重建 |
| 报错后这条信道用不了了 | 声明失败会关闭信道 | 重开一条 `await connection.channel()` |

典型触发场景:给已存在的队列加 TTL / 加 DLX,代码一跑就 406。

---

## 5 publisher confirm

**是什么**:broker 收到消息后回一个确认帧,`publish` 等到它才返回。

**解决什么**:路段①的"消息到底进没进 broker"。没收到确认,`publish` 抛异常,生产端当场知道。

```python
channel = await connection.channel()                  # publisher_confirms 默认 True
confirmation = await exchange.publish(msg, routing_key="normal.key")
print(type(confirmation).__name__)                    # Basic.Ack ← 这就是 broker 的回执
```

| 信道参数 | 默认 | 说明 |
|---|---|---|
| `publisher_confirms` | `True` | **aio-pika 默认就开着**,前三讲每个 `await publish` 都带着回执 |
| `publisher_confirms=False` | | 关掉,publish 发完就返回(返回 None),吞吐更高,但不知道有没有到 |

- 它只保证"到了 broker",不保证"消费者处理成功"——那是 §3 路段和手动 ack 的事
- 日常不需要关

---

## 6 mandatory + on_return_raises

**是什么**:消息到了 broker 但路由不到任何队列时的处理方式。

**解决什么**:默认情况下这种消息被静默丢弃,生产端毫无知觉。开启后当场抛异常。

**默认行为(会丢)**:

```python
channel = await connection.channel()
result = await exchange.publish(msg, routing_key="no.one.binds.this")
# 不抛异常、不打日志。被退回的消息藏在返回值里,但正常没人检查返回值 → 等于丢了
```

**开启后(会炸)**:

```python
strict = await connection.channel(on_return_raises=True)   # ← 关键在这一行
try:
    await strict_exchange.publish(msg, routing_key="no.one.binds.this")
except aio_pika.exceptions.DeliveryError:
    ...  # 记日志 / 告警 / 补偿
```

| 参数 | 位置 | 默认 | 作用 |
|---|---|---|---|
| `mandatory` | `publish(...)` | `True` | 路由不到时,要求 broker 把消息退回而不是丢弃 |
| `on_return_raises` | `connection.channel(...)` | `False` | 收到退回的消息时抛 `DeliveryError` |

- 两个都要有才有效。aio-pika 的 `mandatory` 默认已是 True,所以实际只需加 `on_return_raises=True`
- publish 返回值的两种形态:正常投递 → `Basic.Ack`;路由失败 → 被退回的消息对象

---

## 7 connect_robust

**是什么**:带自动重连的连接。

**解决什么**:常驻消费者遇到网络抖动不至于进程退出。

```python
connection = await aio_pika.connect_robust(RABBITMQ_URL)
```

| | `connect` | `connect_robust` |
|---|---|---|
| 断线 | 抛异常,自己处理 | 自动重连 |
| 重连后 | — | 重放这条连接上的声明、绑定、set_qos、consume |
| 适用 | 一次性脚本、生产者 | 常驻消费者 |

- 只救连接,不救消息:断线瞬间未 ack 的消息 broker 会重投,**幂等仍要自己做**

---

## 8 三件套写在一起

```python
connection = await aio_pika.connect_robust(RABBITMQ_URL)
channel = await connection.channel(on_return_raises=True)       # 路由失败当场抛 → §6

queue = await channel.declare_queue("order.paid.q", durable=True)  # 队列落盘 → §1
await queue.bind(exchange, routing_key="order.paid")

await exchange.publish(                                          # 等 broker 回执 → §5
    aio_pika.Message(body, delivery_mode=aio_pika.DeliveryMode.PERSISTENT),  # 消息落盘 → §2
    routing_key="order.paid",
)
# 消费端:手动 ack + 幂等 → 第 2 讲
```

## 9 完整示例

### durability.py —— 持久化对照组

```python
"""第 4 讲·持久化对照:两个队列、两种消息,看消息能不能活过 broker 重启。

    uv run python "rabbitmq教程/04-消息不丢三件套/durability.py"

跑完后队列故意留在 broker 上不删,方便重启服务后回来看结果。
"""

import asyncio
import os
from pathlib import Path

import aio_pika
from dotenv import load_dotenv

load_dotenv(Path(__file__).parents[2] / ".env")
RABBITMQ_URL = os.environ["RABBITMQ_URL"]


async def main() -> None:
    connection = await aio_pika.connect(RABBITMQ_URL)
    async with connection:
        channel = await connection.channel()

        volatile = await channel.declare_queue("ch4.volatile", durable=False)
        persist = await channel.declare_queue("ch4.persist", durable=True)
        await volatile.purge()
        await persist.purge()

        await channel.default_exchange.publish(
            aio_pika.Message("我是普通消息,重启就没了".encode()),
            routing_key=volatile.name,
        )
        await channel.default_exchange.publish(
            aio_pika.Message(
                "我是持久化消息,重启也还在".encode(),
                delivery_mode=aio_pika.DeliveryMode.PERSISTENT,
            ),
            routing_key=persist.name,
        )
        print("两条消息都发好了,各在各的队列:")
        print("  ch4.volatile  ← 队列不落盘 + 消息不落盘")
        print("  ch4.persist   ← 队列落盘   + 消息落盘")
        print("管理台 Queues 页 Features 列的 D 标志,只有 ch4.persist 有")

        # 故意制造 406:同名队列、不同参数
        print("\n用 durable=False 重新声明已存在的 ch4.persist:")
        try:
            await channel.declare_queue("ch4.persist", durable=False)
        except Exception as e:  # pylint: disable=broad-except
            print(f"  broker 拒绝: {type(e).__name__}: {e}")
            print("  这条信道已被关闭,后续操作需要重开信道")


asyncio.run(main())
```

### publish_confirmed.py —— 确认与路由失败

```python
"""第 4 讲·生产端可靠性:publisher confirm + 路由失败感知。

三个场景:
  一 默认信道 + 路由不到 → 静默丢弃
  二 on_return_raises=True + 路由不到 → 抛 DeliveryError
  三 正常路由 → 返回 broker 的确认帧

    uv run python "rabbitmq教程/04-消息不丢三件套/publish_confirmed.py"
"""

import asyncio
import os
from pathlib import Path

import aio_pika
from dotenv import load_dotenv

load_dotenv(Path(__file__).parents[2] / ".env")
RABBITMQ_URL = os.environ["RABBITMQ_URL"]


async def main() -> None:
    connection = await aio_pika.connect(RABBITMQ_URL)
    async with connection:
        # 场景一:默认信道,路由不到任何队列
        channel = await connection.channel()
        exchange = await channel.declare_exchange(
            "ch4.probe", aio_pika.ExchangeType.DIRECT, durable=True
        )
        result = await exchange.publish(
            aio_pika.Message("我可能哪都到不了".encode()),
            routing_key="no.one.binds.this",
        )
        print("场景一:往没有任何绑定的交换机发消息(默认信道)")
        print(f"  未抛异常,返回值类型 {type(result).__name__}")
        print("  被退回的消息在返回值里,但无异常无日志,实际等于丢弃\n")

        # 场景二:on_return_raises=True
        strict = await connection.channel(on_return_raises=True)
        strict_exchange = await strict.declare_exchange(
            "ch4.probe", aio_pika.ExchangeType.DIRECT, durable=True
        )
        try:
            await strict_exchange.publish(
                aio_pika.Message("再发一次没人要的消息".encode()),
                routing_key="no.one.binds.this",
            )
        except aio_pika.exceptions.DeliveryError:
            print("场景二:同样的消息,on_return_raises=True 的信道")
            print("  抛出 DeliveryError,生产端当场感知\n")

        # 场景三:正常路由 + publisher confirm
        queue = await channel.declare_queue("ch4.probe.target", durable=True)
        await queue.bind(exchange, routing_key="normal.key")
        confirmation = await exchange.publish(
            aio_pika.Message(
                "这条能正常路由".encode(),
                delivery_mode=aio_pika.DeliveryMode.PERSISTENT,
            ),
            routing_key="normal.key",
        )
        print("场景三:正常投递")
        print(f"  返回值类型 {type(confirmation).__name__} ← broker 的确认帧")

        await queue.purge()   # delete 默认拒绝删非空队列
        await queue.delete()
        await exchange.delete()


asyncio.run(main())
```

## 11 速查表

| 配置 | 写在哪 | 默认 | 管什么 |
|---|---|---|---|
| `durable=True` | `declare_queue` | False | 队列定义落盘 |
| `delivery_mode=PERSISTENT` | `Message(...)` | NOT_PERSISTENT | 消息落盘 |
| `publisher_confirms` | `connection.channel()` | **True** | 等 broker 回执 |
| `mandatory` | `publish()` | **True** | 路由失败时退回而非丢弃 |
| `on_return_raises` | `connection.channel()` | False | 收到退回消息时抛 DeliveryError |
| `connect_robust()` | 建连接 | — | 断线自动重连并重放声明 |
