# 锁教程 —— 企业里的并发控制

六讲,从"钱是怎么丢的"讲到 Redis 分布式锁。全部实验跑在仓库 `.env` 里的公网 PostgreSQL 和 Redis 上(不用开 VPN),表名带 `lock01_` ~ `lock06_` 前缀、Redis key 带 `lock05:` 前缀,和别的教程互不干扰。

**仓库里不带你抄的现成 .py**——每个脚本的全文代码只存在于讲义里,照着敲出来、存到对应目录,才是这套教程的用法。配合固定的学习节奏:

```
读开场图(这讲解决什么问题) → 对着讲义敲代码(建议手敲,别复制;
跑脚本、做实验(讲义"跑起来"一节给了原样可复制的命令和预期输出)
→ 回答过关自测(答不上再回头翻)
```

讲义里的 **「敲黑板」** 块是需要牢牢记住的规矩,忘了随时回来扫。

## 学习地图

六讲是一条线:**先看见事故,再学三种解法,最后学会选型**。

```
 01 丢失更新(亲眼看见钱没了)
        │
        ├──────────► 02 悲观锁 FOR UPDATE(先锁后用,别人排队)
        │
        ├──────────► 03 乐观锁 version CAS(先干再说,冲突重试)
        │
        └──────────► 04 唯一约束(数据库替你把的防重锁)+ 锁的内幕与排查
                        │
                        ▼
                   05 Redis 分布式锁(进程外的互斥:定时任务防重、防重复触发)
                        │
                        ▼
                   06 选型决策 + 秒杀综合实战(把 01-05 拼起来)
```

| 讲 | 主题 | 学完你会 | 涉及实验 |
|---|---|---|---|
| 01 | [丢失更新](01-丢失更新/讲义.md) | 竞态条件、读-改-写为什么丢数据 | 两笔入账丢 100;单条原子 UPDATE 不丢 |
| 02 | [悲观锁](02-悲观锁/讲义.md) | FOR UPDATE 排队、NOWAIT、SKIP LOCKED、死锁 | 乙等甲 2 秒;两 worker 抢单不重不漏;死锁现场 40P01 |
| 03 | [乐观锁](03-乐观锁/讲义.md) | version CAS、条件 UPDATE、重试与退避 | 10 人抢 5 部手机:超卖 → 防超卖三连 |
| 04 | [唯一约束](04-唯一约束/讲义.md) | 幂等键、ON CONFLICT、锁家族内幕、查锁 | 支付回调重复入账被拦;天眼查谁堵谁 |
| 05 | [Redis 分布式锁](05-redis锁/讲义.md) | SET NX PX + token + Lua、看门狗续期 | 误删事故三连;进程暴毙锁自愈 |
| 06 | [选型实战](06-选型实战/讲义.md) | 什么场景用什么锁的决策表 | 秒杀:防重 + 防超卖 + 补偿,对账分毫不差 |

## 环境

| 项 | 说明 |
|---|---|
| 数据库 | `.env` 里 `DATABASE_URL` 指向的公网 PostgreSQL 16,不占本机 |
| Redis | `.env` 里 `REDIS_URL` 指向的公网 Redis 7 |
| 依赖 | 仓库 `uv` 环境已备齐(sqlalchemy、asyncpg、redis、python-dotenv) |
| 跑法 | 一律在仓库根目录 `uv run python "锁教程/NN-xxx/xxx.py"` |
| 清场 | 教程表都是 `create_all` + 开场重置,反复跑不影响;想彻底删:`DROP TABLE lock01_account, lock02_account, lock02_jobs, lock02_transfer, lock03_stock, lock04_payment, lock04_account, lock06_stock, lock06_order CASCADE;`,Redis 侧 `DEL lock05:job lock05:watchdog lock05:builtin` |

**和工作的 MySQL 什么关系**:实验用 PostgreSQL(仓库现成的),但每一讲都配了「MySQL 对照」小节——FOR UPDATE / NOWAIT / SKIP LOCKED / 唯一约束两边语义一致,差异(隔离级别、间隙锁)会单独点出。概念完全通用。

## 学完标准

能把下面几句话不假思索地说全,这套教程就毕业了:

- 丢失更新的根因是**应用层把"读-改-写"拆成多次数据库交互,中间没人守门**
- 悲观锁**持锁到事务结束**,乐观锁**不持锁、靠版本号+重试**
- 唯一约束是**最后一道防线**,幂等键设计比任何锁都值钱
- Redis 分布式锁四件套:**NX + 过期时间 + 唯一 token + Lua 释放**
- 选型顺序:**能一条 SQL 就一条 SQL;能数据库锁就别上分布式锁**
