# 第 3 讲 · 并发编排——gather、TaskGroup、限流与超时

> 本讲对应官方文档:[Coroutines and Tasks](https://docs.python.org/zh-cn/3/library/asyncio-task.html) 的后半部分。代码下面就是真实执行结果,不用自己跑。

## 0 模型

第 2 讲会"同时等十件事"了,这一讲学**缰绳**。企业代码里裸奔的 gather 是事故来源——一次并发 5000 个请求,下游直接拉黑你。编排一个并发任务要回答四个问题:

```
   ① 怎么开?   gather / TaskGroup(结构化并发)
   ② 限多少?   Semaphore(并发上限)
   ③ 多久算失败? timeout / wait_for(掐表)
   ④ 谁先处理?  as_completed(先回先处理)/ gather(等齐再说)
```

本讲 API 一览:

| API | 失败行为 | 一句话 |
|---|---|---|
| `asyncio.gather(*aws, return_exceptions=False)` | 默认一个炸,await 处直接抛 | 等齐拿结果列表 |
| `gather(..., return_exceptions=True)` | 不炸,炸的记成异常对象 | 结果里混着异常 |
| `async with asyncio.TaskGroup()` | 一个炸,**其余全部取消** | 结构化并发,3.11+ |
| `async with asyncio.timeout(s)` | 到点取消内部任务,抛 `TimeoutError` | 给一整块掐表 |
| `asyncio.wait_for(aw, timeout)` | 同上 | 给单个等待掐表(老 API) |
| `asyncio.as_completed(aws)` | — | 迭代"完成事件",先回先收 |
| `asyncio.Semaphore(n)` | — | 并发上限 n,拿不到的排队 |
| `asyncio.Lock()` | — | 协程互斥(很少需要,见 §6) |

## 1 `asyncio.gather(*aws, return_exceptions=False)`

同时跑多个协程/Task,**等全部完成**,按提交顺序返回结果列表(耗时 = 最慢那个,不是相加):

```python
import asyncio
import time


async def call_api(name: str, seconds: float) -> dict:
    await asyncio.sleep(seconds)
    print(f"{name} 回来了")
    return {"api": name}


async def main() -> None:
    start = time.monotonic()
    results = await asyncio.gather(call_api("风控", 1), call_api("库存", 2), call_api("积分", 3))
    print(f"拿到 {results},耗时 {time.monotonic() - start:.1f} 秒")


asyncio.run(main())
```

```
风控 回来了
库存 回来了
积分 回来了
拿到 [{'api': '风控'}, {'api': '库存'}, {'api': '积分'}],耗时 3.0 秒
```

默认失败行为:**任何一个抛异常,`await gather(...)` 处立刻抛出它**(其余任务不会被取消,继续跑完但结果丢弃)——适合"一荣俱荣一损俱损"的聚合:

```python
import asyncio


async def ok() -> str:
    await asyncio.sleep(1)
    return "成功的结果"


async def boom() -> None:
    await asyncio.sleep(0.5)
    raise RuntimeError("库存接口 500 了")


async def main() -> None:
    try:
        await asyncio.gather(ok(), boom())
    except RuntimeError as e:
        print(f"gather 抛出:{e}")


asyncio.run(main())
```

```
gather 抛出:库存接口 500 了
```

`return_exceptions=True`:**不抛了**,失败的在结果列表里以异常对象出现,成功照收——适合"聚合展示页,一个挂了别耽误别的":

```python
async def main() -> None:
    results = await asyncio.gather(ok(), boom(), return_exceptions=True)
    for r in results:
        print(f"结果:{r!r}")


asyncio.run(main())
```

```
结果:'成功的结果'
结果:RuntimeError('库存接口 500 了')
```

## 2 `async with asyncio.TaskGroup()`(3.11+)

结构化并发:在 `async with` 块里 `tg.create_task(...)` 注册子任务,**块退出时保证全部结束**;任何一个子任务失败,**其余子任务全部被取消**,所有异常打包成 `ExceptionGroup` 抛出(用 `except*` 按成员类型接):

```python
import asyncio


async def slow(name: str) -> None:
    try:
        await asyncio.sleep(3)
        print(f"{name} 干完了")
    except asyncio.CancelledError:
        print(f"{name} 被取消——兄弟出错,全队撤退")
        raise


async def boom() -> None:
    await asyncio.sleep(0.5)
    raise RuntimeError("炸弹 500 了")


async def main() -> None:
    try:
        async with asyncio.TaskGroup() as tg:
            tg.create_task(slow("慢任务A"))
            tg.create_task(slow("慢任务B"))
            tg.create_task(boom())
    except* RuntimeError as eg:
        print(f"TaskGroup 抛出异常组:{eg.exceptions[0]}")


asyncio.run(main())
```

```
慢任务A 被取消——兄弟出错,全队撤退
慢任务B 被取消——兄弟出错,全队撤退
TaskGroup 抛出异常组:炸弹 500 了
```

炸弹 0.5 秒就炸,3 秒的慢任务**立刻**被取消,没有白跑剩下的 2.5 秒——任务的生死被框在 with 块里,一个不漏(第 1 讲的上下文管理器,在这里管的是"任务")。

**gather 和 TaskGroup 怎么选:失败时兄弟该不该陪葬。** 陪葬(强一致的一组动作)用 TaskGroup;各过各的(聚合展示)用 gather + return_exceptions。官方把 TaskGroup 定为现代推荐写法,新代码优先它。

## 3 `async with asyncio.timeout(delay)`(3.11+)

给**一整块代码**掐总表:块内所有等待共享这个时限,到点未完成,内部任务被取消、`TimeoutError` 从 with 块抛出:

```python
import asyncio


async def flaky(name: str, seconds: float) -> None:
    try:
        await asyncio.sleep(seconds)
        print(f"{name} 赶在表前完成")
    except asyncio.CancelledError:
        print(f"{name} 超时被掐")
        raise


async def main() -> None:
    try:
        async with asyncio.timeout(1.5):
            await asyncio.gather(flaky("快手", 0.5), flaky("慢手", 5))
    except TimeoutError:
        print("整体超时,TimeoutError 冒出来了")


asyncio.run(main())
```

```
快手 赶在表前完成
慢手 超时被掐
整体超时,TimeoutError 冒出来了
```

慢手要 5 秒,表只有 1.5 秒——到点**取消**(不是干等它跑完再报错),任务内部以 `CancelledError` 感知。注意 `raise` 要放行,别把取消吞了。配套的 `asyncio.timeout_at(when)` 按绝对时刻掐表,循环里"每轮重置时限"的场景用。

## 4 `asyncio.wait_for(aw, timeout)`

timeout 的老前辈,给**单个等待**掐表,超时取消该任务并抛 `TimeoutError`。老代码大量存在,新代码块状超时优先 `asyncio.timeout`:

```python
import asyncio


async def slow() -> str:
    await asyncio.sleep(5)
    return "慢结果"


async def main() -> None:
    try:
        await asyncio.wait_for(slow(), timeout=1)
    except TimeoutError:
        print("1 秒没回来,任务被取消,TimeoutError")


asyncio.run(main())
```

```
1 秒没回来,任务被取消,TimeoutError
```

| | `asyncio.timeout(s)` | `wait_for(aw, s)` |
|---|---|---|
| 范围 | 一块代码(可含多个 await/gather) | 单个 await 的任务 |
| 年代 | 3.11+,官方推荐 | 老代码常见 |

## 5 `asyncio.as_completed(aws)`

返回一个迭代器,每次迭代**等到"下一个完成的任务"**——处理顺序按完成先后,不按提交先后。搜索联想框、流式渲染用它:

```python
import asyncio
import time


async def main() -> None:
    start = time.monotonic()
    tasks = [asyncio.create_task(asyncio.sleep(d)) for d in (3, 1, 2)]
    for finished in asyncio.as_completed(tasks):
        await finished
        print(f"收下一个(第 {time.monotonic() - start:.0f} 秒)——按完成顺序")


asyncio.run(main())
```

```
收下一个(第 1 秒)——按完成顺序
收下一个(第 2 秒)——按完成顺序
收下一个(第 3 秒)——按完成顺序
```

提交顺序 (3,1,2),回收顺序 1、2、3 秒。对比 gather:gather 必须等齐才拿到全部,适合"拼完整页面";as_completed 来一个处理一个,适合"渐进展示"。

## 6 `asyncio.Semaphore(value)`:并发上限

对外"全部并发",对内"最多同时 n 个"。内部计数器:进块减一、出块加一,为 0 时后来的排队等:

```python
import asyncio
import time


async def main() -> None:
    sem = asyncio.Semaphore(3)  # 只有 3 个窗口
    start = time.monotonic()

    async def request(i: int) -> None:
        async with sem:  # 拿到窗口才进,拿不到排队
            print(f"请求{i:02d} 进窗口(第 {time.monotonic() - start:.1f} 秒)")
            await asyncio.sleep(0.5)

    await asyncio.gather(*(request(i) for i in range(6)))
    print(f"全部完成,耗时 {time.monotonic() - start:.1f} 秒(6÷3 窗口=2 批×0.5 秒)")


asyncio.run(main())
```

```
请求00 进窗口(第 0.0 秒)
请求01 进窗口(第 0.0 秒)
请求02 进窗口(第 0.0 秒)
请求03 进窗口(第 0.5 秒)
请求04 进窗口(第 0.5 秒)
请求05 进窗口(第 0.5 秒)
全部完成,耗时 1.0 秒(6÷3 窗口=2 批×0.5 秒)
```

任一时刻窗口里最多 3 个。**凡是"循环里调外部接口",gather 之前先问一句——并发上限在哪?** 没有上限的 gather 是全量齐发,生产大列表一来就是自我 DDoS。经验值:调下游 HTTP 5~20 并发起步。

## 7 `asyncio.Lock()`:什么时候才真的需要

第 2 讲说过"await 之间天然原子",所以纯内存变量几乎不用锁。**例外:读-改-写跨越了 await**——读到旧值、await 让位给别人、回来写回,窗口开在了 await 两侧,照样丢更新(和锁教程第 1 讲数据库丢更新同构):

```python
import asyncio

counter = 0
lock = asyncio.Lock()


async def bad() -> None:
    """两个 await 之间读旧值、第二个 await 后写回 —— 窗口跨越了 await,会丢。"""
    global counter
    for _ in range(5):
        tmp = counter
        await asyncio.sleep(0)  # 让位:别人此刻也读到同一个 tmp
        counter = tmp + 1


async def good() -> None:
    """读改写全程持锁(协程锁不用等系统,只是排队)。"""
    global counter
    for _ in range(5):
        async with lock:
            tmp = counter
            await asyncio.sleep(0)
            counter = tmp + 1


async def main() -> None:
    global counter
    counter = 0
    await asyncio.gather(bad(), bad())
    print(f"无锁宽窗口:counter = {counter}(期望 10)")
    counter = 0
    await asyncio.gather(good(), good())
    print(f"加锁宽窗口:counter = {counter}(期望 10)")


asyncio.run(main())
```

```
无锁宽窗口:counter = 5(期望 10)
加锁宽窗口:counter = 10(期望 10)
```

同族还有 `asyncio.Event`(等一个信号)、`asyncio.Queue`(协程间生产者/消费者队列)——Queue 在 worker 类代码里真实常用,用到再查官方文档。**纪律:协程间共享可变状态,优先改设计(局部变量/队列传递);真要共享读写,锁教程第 2 讲的原则照搬——锁内别 await,窗口越短越好。**

## 8 速查表

| 问题 | API | 心法 |
|---|---|---|
| 等齐拿全部 | `gather`(失败语义先想好) | 要不要 return_exceptions |
| 同生共死 | `async with TaskGroup()` | 一炸全取消,`except*` 接 |
| 限并发 | `asyncio.Semaphore(n)` | 对外全并发,对内 n 条道 |
| 整块时限 | `async with asyncio.timeout(s)` | 超时=取消 |
| 单个时限 | `wait_for(aw, s)` | 老代码常见 |
| 流式回收 | `as_completed(tasks)` | 先回先处理 |
| 跨 await 的读改写 | `asyncio.Lock()` | 很少需要;需要时锁内别 await |
