# 第 3 讲 · 并发编排——gather、信号量与超时

## 0 模型

上一讲会"同时等十件事"了,这一讲学**缰绳**。企业代码里裸奔的 gather 是事故来源——一次并发 5000 个请求,下游直接拉黑你:

```
   编排一个并发任务要回答四个问题:
   ① 怎么开?   create_task / gather / TaskGroup
   ② 限多少?   Semaphore(并发上限)
   ③ 多久算失败? timeout(整体掐表)
   ④ 谁先处理?  as_completed(先回先处理)/ gather(等齐再说)
```

| API | 一句话 | 失败行为 |
|---|---|---|
| `asyncio.gather(*aws)` | 等齐拿结果列表 | 默认一个炸全炸(其余继续跑完但结果丢弃) |
| `gather(..., return_exceptions=True)` | 等齐,炸的记成异常对象 | 不炸,结果里混着异常 |
| `async with asyncio.TaskGroup()` | 结构化并发:块退出时保证全部结束 | 一个炸,**其余全部取消**,异常打包成组 |
| `asyncio.Semaphore(n)` | 并发上限 n,拿不到的排队 | — |
| `async with asyncio.timeout(s)` | 整块掐表 | 超时取消内部任务,抛 `TimeoutError` |
| `asyncio.as_completed(tasks)` | 迭代"完成事件",先回先处理 | — |

gather 和 TaskGroup 怎么选:**"要不要一荣俱荣一损俱损"**。聚合展示页(一个挂了别的不耽误)用 gather + return_exceptions;强一致的一组动作(一个失败其余没意义)用 TaskGroup,它会自动取消兄弟,不浪费。

## 1 敲代码:`gather_group.py`

```python
"""gather 与 TaskGroup:聚合下游、异常处理、结构化并发的取消。"""

import asyncio
import time


def log(message: str) -> None:
    print(f"[{time.strftime('%H:%M:%S')}] {message}", flush=True)


async def call_api(name: str, seconds: float, fail: bool = False) -> dict:
    """模拟调一个下游接口:慢,可能挂。"""
    log(f"{name} 出发")
    await asyncio.sleep(seconds)
    if fail:
        raise RuntimeError(f"{name} 500 了")
    log(f"{name} 成功返回")
    return {"api": name}


async def main() -> None:
    log("=== 第一幕:聚合三个下游,串行 6 秒 → gather 3 秒 ===")
    start = time.monotonic()
    results = await asyncio.gather(
        call_api("风控", 1),
        call_api("库存", 2),
        call_api("积分", 3),
    )
    log(f"gather 拿到 {len(results)} 个结果,耗时 {time.monotonic() - start:.1f} 秒")

    log("=== 第二幕:gather 默认一个炸全炸 ===")
    try:
        await asyncio.gather(call_api("风控", 1), call_api("库存", 2, fail=True))
    except RuntimeError as e:
        log(f"gather 抛出:{e}(已完成的那个结果也不要了)")

    log("=== 第三幕:return_exceptions=True,炸的记成异常,其余照收 ===")
    results = await asyncio.gather(
        call_api("风控", 1),
        call_api("库存", 2, fail=True),
        call_api("积分", 3),
        return_exceptions=True,
    )
    for r in results:
        log(f"结果是:{r!r}")

    log("=== 第四幕:TaskGroup,一个炸,兄弟姐妹全体取消 ===")

    async def slow_one(name: str, seconds: float) -> None:
        try:
            await asyncio.sleep(seconds)
            log(f"{name} 干完了")
        except asyncio.CancelledError:
            log(f"{name} 被取消了——兄弟出错,全队撤退")
            raise

    try:
        async with asyncio.TaskGroup() as tg:
            tg.create_task(slow_one("慢任务A", 3))
            tg.create_task(slow_one("慢任务B", 3))
            tg.create_task(call_api("快炸弹", 1, fail=True))
    except* RuntimeError as eg:
        log(f"TaskGroup 冒出来的异常:{eg.exceptions[0]}")


asyncio.run(main())
```

`except*` 是新语法(Python 3.11+):TaskGroup 抛的是 `ExceptionGroup`,里面可能打包多个异常,`except* 类型` 按"组里的成员类型"匹配。

## 3 敲代码:`flow_control.py`(限流 / 掐表 / 先回先收)

```python
"""流量三件套:Semaphore 限并发、timeout 掐表、as_completed 谁快收谁。"""

import asyncio
import time


def log(message: str) -> None:
    print(f"[{time.strftime('%H:%M:%S')}] {message}", flush=True)


async def main() -> None:
    log("=== 第一幕:20 个请求,只有 5 个窗口(Semaphore)===")
    sem = asyncio.Semaphore(5)

    async def request(i: int) -> None:
        async with sem:  # 拿到窗口才进,拿不到排队
            log(f"请求{i:02d} 进窗口")
            await asyncio.sleep(0.5)
            log(f"请求{i:02d} 完成,腾出窗口")

    start = time.monotonic()
    await asyncio.gather(*(request(i) for i in range(20)))
    log(
        f"20 个请求全部完成,耗时 {time.monotonic() - start:.1f} 秒(20÷5 个窗口=4 批×0.5 秒≈2 秒)"
    )

    log("=== 第二幕:timeout 掐表,超时的任务直接取消 ===")

    async def flaky(name: str, seconds: float) -> None:
        try:
            await asyncio.sleep(seconds)
            log(f"{name} 赶在表前完成了")
        except asyncio.CancelledError:
            log(f"{name} 超时被掐")
            raise

    try:
        async with asyncio.timeout(1.5):
            await asyncio.gather(flaky("快手", 0.5), flaky("慢手", 5))
    except TimeoutError:
        log("整体超时,TimeoutError 冒出来了")

    log("=== 第三幕:as_completed,谁先回先处理谁 ===")
    start = time.monotonic()
    tasks = [asyncio.create_task(asyncio.sleep(d)) for d in (3, 1, 2)]
    for finished in asyncio.as_completed(tasks):
        await finished
        log(f"收下一个(第 {time.monotonic() - start:.0f} 秒)——按完成顺序,不按提交顺序")


asyncio.run(main())
```

三件事对着日志确认:

- 第一幕:任一时刻在窗口里的请求**永远只有 5 个**,总耗时 ≈ 批次数 × 单个耗时——对外"20 个全并发",对内"永远 5 个",下游毫无压力
- 第二幕:慢手 5 秒,表只有 1.5 秒 → 到点**取消**(不是等它跑完再报错),`CancelledError` 在任务内部冒出来,记得让它继续 `raise`
- 第三幕:提交顺序 (3,1,2),回收顺序 1、2、3 秒——流式处理用它,别等最慢的拖全体

**敲黑板:凡是"循环里调外部接口",gather 之前先问一句——并发上限在哪?** 没有 Semaphore 的 gather 是全量齐发,测试环境没事(量小),生产大列表一来就是自我 DDoS。经验值:调下游 HTTP 5~20 并发起步,数据库连接池上限减一留余量。

`asyncio.timeout`(3.11+)是 `wait_for` 的现代替身,**掐的是"块内所有事"的整体时间**,配 gather 天然是"这批请求总共最多等 N 秒"。

## 6 速查表

| API | 用途 | 一行心法 |
|---|---|---|
| `gather(*aws)` | 并发等齐 | 要不要 return_exceptions,先想失败语义 |
| `async with TaskGroup()` | 结构化并发 | 一个炸全队撤,异常用 except* 接 |
| `Semaphore(n)` | 并发上限 | 对外全并发,对内 n 条道 |
| `async with asyncio.timeout(s)` | 整体掐表 | 超时=取消,不是干等 |
| `as_completed(tasks)` | 流式回收 | 先回先处理 |
