# 第 2 讲 · 协程与事件循环——asyncio 基础 API

> 本讲对应官方文档:[Coroutines and Tasks](https://docs.python.org/zh-cn/3/library/asyncio-task.html) 的前半部分。代码下面就是真实执行结果,不用自己跑。

## 0 模型

asyncio 的全部秘密一张图:

```
        事件循环(一个线程,唯一的主角)
   ┌──────────────────────────────────────────────┐
   │   时刻    协程A          协程B          协程C   │
   │   t0    跑到 await ──┐                        │
   │   t1                 │         跑到 await ──┐ │
   │   t2                 ▼                       ▼ │
   │        A 在等网络(挂起,不占线程)  B 在等网络      │
   │   t3    ……谁的网络先回来,谁先恢复运行……           │
   └──────────────────────────────────────────────┘
   同一时刻只有一个协程在跑;等待的协程让出线程给别的协程
```

和"多线程并发"的根本区别:**协程的切换点是代码里显式写的 await,线程的切换点是操作系统随时插进来的**。前者因此不需要锁保护 `x += 1`(await 之外没人能打断),后者必须加锁(第 4 讲实测)。

本讲 API 一览:

| API | 作用一句话 |
|---|---|
| `async def` / `await` | 定义协程 / 让位点 |
| `asyncio.run(coro)` | 程序入口:建事件循环、跑完、关闭 |
| `asyncio.sleep(delay)` | 异步等待(对比 `time.sleep` 毒药) |
| `asyncio.create_task(coro)` | 立刻把协程丢上调度台,不等它 |
| `asyncio.gather(*aws)` | 同时等多个(第 3 讲展开) |

## 1 `async def` / `await`:定义协程、让出控制权

**调用 `async def` 函数不会执行它**,只会返回一个协程对象;`await` 它,代码才开始跑。这是新手第一大坑的根源:

```python
import asyncio


async def hello():
    print("hello 跑了")


coro = hello()
print("只定义、不 await:", coro)

print("---")
result = asyncio.run(hello())
print("asyncio.run 跑完,返回值:", result)
```

```
只定义、不 await: <coroutine object hello at 0x101c731c0>
---
hello 跑了
asyncio.run 跑完,返回值: None
<sys>:0: RuntimeWarning: coroutine 'hello' was never awaited
```

(最后一行就是那个"只定义没跑"的 coro 在程序退出时留下的遗言——正好引出下面的坑。)

漏写 `await` 不报错、只是"没跑",唯一的线索是解释器退出时的警告(协程对象被销毁时触发):

```python
async def hello():
    print("hello")


hello()  # 忘了 await
print("程序结束")
```

```
warn_demo.py:5: RuntimeWarning: coroutine 'hello' was never awaited
  hello()  # 忘了 await
RuntimeWarning: Enable tracemalloc to get the object allocation traceback
程序结束
```

**习惯:看到 `async def`,调用处必带 await。** 下游拿到"协程对象当结果用"的 bug,炸点在千里之外。

`await` 的语义:**让位点**。执行到 `await`,当前协程把控制权交还事件循环、自己去等;等的事完成后再回来接着跑。两个协程因此"轮流掌勺":

```python
import asyncio


async def cook(name: str) -> None:
    for i in range(1, 3):
        print(f"{name}:第 {i} 道菜下锅")
        await asyncio.sleep(0.1)
        print(f"{name}:第 {i} 道菜出锅")


async def main() -> None:
    await asyncio.gather(cook("甲厨"), cook("乙厨"))


asyncio.run(main())
```

```
甲厨:第 1 道菜下锅
乙厨:第 1 道菜下锅
甲厨:第 1 道菜出锅
甲厨:第 2 道菜下锅
乙厨:第 1 道菜出锅
乙厨:第 2 道菜下锅
甲厨:第 2 道菜出锅
乙厨:第 2 道菜出锅
```

日志严格交错——不是同时跑,是**等的时候让别人跑**。

## 2 `asyncio.run(coro, *, debug=None)`

程序入口:新建一个事件循环,跑完传入的主协程,关闭循环并返回结果。**一个程序顶层调用一次**;循环里再调会报错(已经有一个循环在跑):

```python
import asyncio


async def inner():
    await asyncio.sleep(0.1)


async def main():
    asyncio.run(inner())  # 里面已经有事件循环在跑了


asyncio.run(main())
```

```
RuntimeError: asyncio.run() cannot be called from a running event loop
```

已经在循环里(比如 Celery worker 的常驻循环、Jupyter)时,正确姿势是 `await` 或拿当前循环用(第 5 讲的工作项目场景)。

## 3 `asyncio.sleep(delay, result=None)`:唯一正确的等待

暂停当前协程 `delay` 秒,**等待期间让出线程**;`result` 参数是睡醒后的返回值。`time.sleep` 是它的反面——不认识 asyncio,抱着线程不放,冻结整个事件循环:

```python
import asyncio
import time

start = time.monotonic()


def log(msg: str) -> None:
    print(f"[{time.monotonic() - start:5.2f}s] {msg}", flush=True)


async def heartbeat() -> None:
    for i in range(8):
        log(f"心跳 {i}")
        await asyncio.sleep(0.2)


async def blocker() -> None:
    await asyncio.sleep(0.3)  # 先让心跳跑两拍
    log("time.sleep(0.6) 开始 —— 抱着线程不放")
    time.sleep(0.6)
    log("time.sleep 结束")


async def main() -> None:
    await asyncio.gather(heartbeat(), blocker())


asyncio.run(main())
```

```
[ 0.00s] 心跳 0
[ 0.20s] 心跳 1
[ 0.30s] time.sleep(0.6) 开始 —— 抱着线程不放
[ 0.90s] time.sleep 结束
[ 0.90s] 心跳 2
[ 1.10s] 心跳 3
[ 1.31s] 心跳 4
[ 1.51s] 心跳 5
[ 1.71s] 心跳 6
[ 1.91s] 心跳 7
```

看 0.30s→0.90s:**心跳 1 和心跳 2 之间整整静默了 0.6 秒**——`time.sleep` 期间事件循环线程被占着,谁都跑不了。生产事故版本就是"异步路由里调了个同步库,所有请求集体超时"。

特殊用法 `asyncio.sleep(0)`:纯让位一次,不等待——用于"轮到别人跑",常出现在测试和调度代码里。

## 4 `asyncio.create_task(coro, *, name=None)`

把协程**立即包装成 Task 丢上调度台**,函数立刻返回 Task 对象——协程从此在后台推进,不用等。对比:直接 `await coro` 是顺序执行,先跑完再走。

```python
import asyncio
import time


async def download(name: str) -> str:
    await asyncio.sleep(1)
    return f"{name}的结果"


async def main() -> None:
    start = time.monotonic()
    r1 = await download("甲")
    r2 = await download("乙")
    print(f"串行:{r1}, {r2},耗时 {time.monotonic() - start:.1f} 秒")

    start = time.monotonic()
    t1 = asyncio.create_task(download("甲"))
    t2 = asyncio.create_task(download("乙"))
    r1, r2 = await t1, await t2
    print(f"并发:{r1}, {r2},耗时 {time.monotonic() - start:.1f} 秒")


asyncio.run(main())
```

```
串行:甲的结果, 乙的结果,耗时 2.0 秒
并发:甲的结果, 乙的结果,耗时 1.0 秒
```

| 写法 | 含义 |
|---|---|
| `r = await download()` | 在这里等它跑完,顺序执行 |
| `t = asyncio.create_task(download())` | 立刻调度,先干别的;之后 `await t` 收结果 |
| `asyncio.gather(t1, t2)` | 同时等一批(第 3 讲) |

官网点名的坑:**保存 create_task 的返回值**。没有任何变量引用的 Task 可能被垃圾回收,任务中途无声消失——别的协程还在等它的结果,等来一场空。多任务统一用容器装起来再 gather。

顺带一个重要事实,事件循环单线程的直接推论——**await 之间的代码天然原子**:

```python
import asyncio

counter = 0


async def bump(worker: str) -> None:
    global counter
    for _ in range(10000):
        counter += 1          # 读写之间没有 await,天然原子
        if _ % 1000 == 0:
            await asyncio.sleep(0)  # 让位,但让位点不在 += 中间


async def main() -> None:
    await asyncio.gather(*(bump(f"工人{i}") for i in range(4)))
    print(f"counter = {counter}(期望 40000,一个不丢)")


asyncio.run(main())
```

```
counter = 40000(期望 40000,一个不丢)
```

同一份代码换成线程就丢数千次(第 4 讲实测)。**协程世界"危险"的定义变了**:不怕"两段代码同时执行"(不可能),怕"await 点两侧数据被人改了"——两个 await 之间读过的数据,第二个 await 之后要用,就得重新读或上锁(数据库侧就是锁教程的 FOR UPDATE / version)。

## 5 速查表

| API | 一句话 |
|---|---|
| `async def` / `await` | 定义协程 / 让位点;不 await 不执行 |
| `asyncio.run(main())` | 入口,建循环跑完关;不可嵌套 |
| `asyncio.sleep(n)` | 异步等待;`sleep(0)` 纯让位 |
| `time.sleep(n)` | ❌ 协程毒药,冻结全场 |
| `asyncio.create_task(coro)` | 立即调度;保存引用防 GC |
