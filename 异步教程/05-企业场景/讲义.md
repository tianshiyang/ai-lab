# 第 5 讲 · 企业场景——从 FastAPI 到 Celery

> 本讲对应官方文档:[FastAPI Lifespan Events](https://fastapi.tiangolo.com/advanced/events/)、[Dependencies with yield](https://fastapi.tiangolo.com/tutorial/dependencies/dependencies-with-yield/)。前四讲的零件在这里拼成工作项目的骨架,代码下面就是真实执行结果。

## 0 全图

```
 uvicorn 启动进程
    │
    ▼
 lifespan(第 1 讲:@asynccontextmanager)──── 建连接池 / 关停释放
    │
    ▼
 事件循环 + 若干协程(第 2、3 讲)
    │  每个请求:
    ▼
 FastAPI 路由(async def)
    │  Depends(get_db_session)  ← yield 依赖(第 1 讲):借出会话,管好收尾
    ▼
 service 层(业务逻辑,FOR UPDATE / version ← 锁教程)
    │
    ▼
 响应返回,依赖收尾:成功 commit / 异常 rollback / 必 close

 旁边:Celery worker 进程(第 4 讲:CPU/慢活的归宿,常驻事件循环跑任务)
```

四讲各就各位:**上下文管理器是地基(资源生命周期),协程是主干(请求并发),编排是缰绳(下游并发),线程/进程是外挂(阻塞桥接 + 重活外包)**。

## 1 `lifespan`:进程级的进门出门

```
@asynccontextmanager
async def lifespan(app: FastAPI):
    启动代码          # 进程起来时跑一次:建连接池、预热缓存
    yield             # 服务运行期间,一直停在这
    关停代码          # 收到 SIGTERM/Ctrl+C 后跑:释放连接池
app = FastAPI(lifespan=lifespan)
```

就是第 1 讲的 `@asynccontextmanager`,只不过 with 的"块"是**整个进程的生命周期**。最小可跑版:

```python
from contextlib import asynccontextmanager

from fastapi import FastAPI


@asynccontextmanager
async def lifespan(app: FastAPI):
    print(">>> 启动:建连接池、预热缓存(进程级,一次)")
    yield  # ← 服务运行期间,一直停在这
    print(">>> 关停:释放连接池(Ctrl+C 或 SIGTERM 后走到这)")


app = FastAPI(lifespan=lifespan)


@app.get("/ping")
async def ping() -> dict:
    return {"msg": "pong"}
```

启动、访问一次、Ctrl+C,服务器日志:

```
INFO:     Started server process [1808]
INFO:     Application startup complete.
>>> 启动:建连接池、预热缓存(进程级,一次)
INFO:     127.0.0.1:59826 - "GET /ping HTTP/1.1" 200 OK
INFO:     Shutting down

>>> 关停:释放连接池(Ctrl+C 或 SIGTERM 后走到这)
```

## 2 yield 依赖:请求级的进门出门

```
async def get_db_session() -> AsyncIterator[AsyncSession]:
    session = Session()
    try:
        yield session          # 借出去,路由代码在这里用
        await session.commit() # 响应成功:提交
    except Exception:
        await session.rollback()  # 路由出事:回滚
        raise                     # 异常继续抛给全局处理器
    finally:
        await session.close()     # 无论如何:关闭
DbSession = Annotated[AsyncSession, Depends(get_db_session)]
```

FastAPI 的规则:**依赖函数里 yield,yield 之前是"进请求",之后是"出响应"**——框架内部用 AsyncExitStack 替你走完整个生命周期(第 1 讲协议的框架落地)。**注意:必须是原生 async 生成器,不能用 `@asynccontextmanager` 包**,包了就变"返回管家的普通函数",启动直接 TypeError。

带日志的最小可跑版(存 `dep_demo.py`,连公网 PG):

```python
async def get_db_session() -> AsyncIterator[AsyncSession]:
    """请求级会话:借出 → 成功 commit / 异常 rollback → 必 close。"""
    session = Session()
    print(">>> 借出会话", flush=True)
    try:
        yield session
        await session.commit()
        print(">>> 请求成功,自动提交", flush=True)
    except Exception:
        await session.rollback()
        print(">>> 请求出事,自动回滚", flush=True)
        raise
    finally:
        await session.close()
        print(">>> 关闭会话", flush=True)


DbSession = Annotated[AsyncSession, Depends(get_db_session)]


@app.post("/orders")
async def create_order(session: DbSession, title: str = "new-order") -> dict:
    session.add(Order(title=title))
    return {"msg": f"已落库:{title}"}
```

发两个请求(`curl -s -X POST "http://127.0.0.1:8012/orders?title=lunch"` 两次),服务器日志:

```
>>> 借出会话
INFO:     127.0.0.1:60372 - "POST /orders?title=lunch" HTTP/1.1" 200 OK
>>> 请求成功,自动提交
>>> 关闭会话
>>> 借出会话
INFO:     127.0.0.1:60373 - "POST /orders?title=dinner" HTTP/1.1" 200 OK
>>> 请求成功,自动提交
>>> 关闭会话
```

每个请求一借一还,路由代码里**一个 commit/rollback/close 都不用写**——这就是工作项目"service 层禁止出现 commit/rollback"能成立的机制。`Annotated[...]` 类型别名(工作项目 `common/dependencies.py` 的 `DbSession`/`CurrentUser`)让路由签名只剩 `session: DbSession`,团队共用一处定义。

## 3 综合实战:迷你转账 API

四讲 + 锁教程拼成一个文件。要点全部在注释里:

```python
"""迷你转账 API:工作项目全套骨架的浓缩版——lifespan、请求级会话依赖、悲观锁。"""

import asyncio
import os
from collections.abc import AsyncIterator
from contextlib import asynccontextmanager
from pathlib import Path
from typing import Annotated

import uvicorn
from dotenv import load_dotenv
from fastapi import Depends, FastAPI, Query
from sqlalchemy import String, delete, select
from sqlalchemy.ext.asyncio import AsyncSession, async_sessionmaker, create_async_engine
from sqlalchemy.orm import DeclarativeBase, Mapped, mapped_column

load_dotenv(Path(__file__).parents[2] / ".env")
DATABASE_URL = os.environ["DATABASE_URL"]


class Base(DeclarativeBase):
    pass


class Account(Base):
    __tablename__ = "async05_account"

    id: Mapped[int] = mapped_column(primary_key=True)
    name: Mapped[str] = mapped_column(String(20))
    balance: Mapped[int]


engine = create_async_engine(DATABASE_URL)
Session = async_sessionmaker(engine, expire_on_commit=False)


@asynccontextmanager
async def lifespan(app: FastAPI):
    """进程级资源:启动时建表,关停时释放连接池。"""
    async with engine.begin() as conn:
        await conn.run_sync(Base.metadata.create_all)
    yield
    await engine.dispose()


app = FastAPI(lifespan=lifespan)


async def get_db_session() -> AsyncIterator[AsyncSession]:
    """请求级会话:成功自动 commit,异常自动 rollback,结束必 close(yield 依赖)。"""
    session = Session()
    try:
        yield session
        await session.commit()
    except Exception:
        await session.rollback()
        raise
    finally:
        await session.close()


DbSession = Annotated[AsyncSession, Depends(get_db_session)]


@app.post("/reset")
async def reset(session: DbSession) -> dict:
    """两账号各重置为 1000。"""
    await session.execute(delete(Account))
    session.add_all(
        [
            Account(id=1, name="ahua", balance=1000),
            Account(id=2, name="acao", balance=1000),
        ]
    )
    return {"msg": "ok:两账号各 1000,总额 2000"}


@app.get("/balance")
async def balance(session: DbSession) -> dict:
    """查所有账号余额和总额。"""
    rows = (
        await session.execute(
            select(Account.id, Account.name, Account.balance).order_by(Account.id)
        )
    ).all()
    return {
        "accounts": [{"id": r.id, "name": r.name, "balance": r.balance} for r in rows],
        "total": sum(r.balance for r in rows),
    }


@app.post("/transfer")
async def transfer(
    session: DbSession,
    from_id: Annotated[int, Query(description="转出账号")] = 1,
    to_id: Annotated[int, Query(description="转入账号")] = 2,
    amount: Annotated[int, Query(description="金额")] = 100,
) -> dict:
    """正确版:两行按 id 排序后 FOR UPDATE,对向转账也不会死锁。"""
    stmt = (
        select(Account).where(Account.id.in_([from_id, to_id])).order_by(Account.id).with_for_update()
    )
    accounts = {a.id: a for a in (await session.execute(stmt)).scalars()}
    if from_id not in accounts or to_id not in accounts:
        return {"msg": "账号不存在"}
    if accounts[from_id].balance < amount:
        return {"msg": "余额不足"}
    await asyncio.sleep(0.5)  # 拉长持锁窗口,方便观察并发
    accounts[from_id].balance -= amount
    accounts[to_id].balance += amount
    return {"msg": f"{from_id} -> {to_id} 转 {amount} 成功"}


@app.post("/transfer-naive")
async def transfer_naive(
    session: DbSession,
    from_id: Annotated[int, Query(description="转出账号")] = 1,
    to_id: Annotated[int, Query(description="转入账号")] = 2,
    amount: Annotated[int, Query(description="金额")] = 100,
) -> dict:
    """错误示范:先读、再睡、再写,丢失更新原样搬进 API。"""
    rows = (
        await session.execute(select(Account).where(Account.id.in_([from_id, to_id])))
    ).scalars()
    accounts = {a.id: a for a in rows}
    await asyncio.sleep(0.5)
    accounts[from_id].balance -= amount
    accounts[to_id].balance += amount
    return {"msg": f"{from_id} -> {to_id} 转 {amount} 成功(其实未必)"}


if __name__ == "__main__":
    uvicorn.run(app, host="127.0.0.1", port=8010)
```

启动后做并发实验(两个终端,或一条命令里 `&` 并发):

```
curl -s -X POST "http://127.0.0.1:8010/reset"; echo
curl -s "http://127.0.0.1:8010/balance"; echo
# 锁版:同一秒发出两笔对向转账
curl -s -X POST "http://127.0.0.1:8010/transfer?from_id=1&to_id=2&amount=200" &
curl -s -X POST "http://127.0.0.1:8010/transfer?from_id=2&to_id=1&amount=300" &
wait; curl -s "http://127.0.0.1:8010/balance"; echo
```

```
{"msg":"ok:两账号各 1000,总额 2000"}
{"accounts":[{"id":1,"name":"ahua","balance":1000},{"id":2,"name":"acao","balance":1000}],"total":2000}
{"msg":"1 -> 2 转 200 成功"}{"msg":"2 -> 1 转 300 成功"}
{"accounts":[{"id":1,"name":"ahua","balance":1100},{"id":2,"name":"acao","balance":900}],"total":2000}
```

锁版:1000-200+300=1100、1000+200-300=900,分毫不差(第二笔在锁上排队了 0.5 秒)。换成无锁版 `/transfer-naive`(先 reset):

```
curl -s -X POST "http://127.0.0.1:8010/reset" > /dev/null
curl -s -X POST "http://127.0.0.1:8010/transfer-naive?from_id=1&to_id=2&amount=200" &
curl -s -X POST "http://127.0.0.1:8010/transfer-naive?from_id=2&to_id=1&amount=300" &
wait; curl -s "http://127.0.0.1:8010/balance"; echo
```

```
{"msg":"1 -> 2 转 200 成功(其实未必)"}{"msg":"2 -> 1 转 300 成功(其实未必)"}
{"accounts":[{"id":1,"name":"ahua","balance":1300},{"id":2,"name":"acao","balance":700}],"total":2000}
```

**那笔 200 的转账整个蒸发了**(正确应 1100/900,实得 1300/700)。总额还是 2000——每笔自身是平衡的——但一笔凭空消失。这就是锁教程第 1 讲的丢失更新穿上 HTTP 外衣:两个请求各自"读→睡 0.5 秒→写",后提交的把先提交的整行覆盖。多跑几次哪笔蒸发是随机的,偶尔还能碰巧出对的结果——**事故的可怕正在于时有时无,压测必现,线上偶发**。

## 4 Celery worker:常驻事件循环

worker 是独立进程(第 4 讲:天然绕开 GIL),里面跑协程的正确姿势是**循环建一次、常驻复用**——每个任务来了在同一个循环上 `run_until_complete`,而不是每个任务 `asyncio.run` 反复建拆循环(第 2 讲说过嵌套/反复建的代价)。原理浓缩:

```python
import asyncio

loop = asyncio.new_event_loop()  # worker 启动时建一次(常驻)


async def job(i: int) -> str:
    await asyncio.sleep(0.1)
    return f"任务{i}完成"


# 每来一个任务,都在同一个循环上跑,不重建
for i in range(3):
    result = loop.run_until_complete(job(i))
    print(f"{result}(循环 id={id(loop)},始终同一个)")

loop.close()
print("worker 退出时才关循环")
```

```
任务0完成(循环 id=4322580464,始终同一个)
任务1完成(循环 id=4322580464,始终同一个)
任务2完成(循环 id=4322580464,始终同一个)
worker 退出时才关循环
```

工作项目的 worker 正是这种写法;任务怎么编排、重试、路由,见 celery 教程。

## 5 异步服务的五大事故模板

生产事故翻来覆去就这几种,每条都能在前四讲找到出处:

| # | 事故 | 根因 | 解法(出处) |
|---|---|---|---|
| 1 | 一个接口慢,所有接口跟着超时 | async 路由里混了同步阻塞调用(同步 SDK、`time.sleep`、pandas 算大表) | `to_thread` 桥接;重活丢 Celery(第 4 讲) |
| 2 | 代码"没跑",结果全是空,还不报错 | 漏了 await,拿到协程对象当结果用 | 盯 `RuntimeWarning: ... never awaited`(第 2 讲) |
| 3 | gather 齐发打爆下游 | 没有并发上限 | `Semaphore`;连接池上限(第 3 讲) |
| 4 | 偶发数据错乱、丢更新 | 并发读写没锁 | 锁教程全家桶 |
| 5 | 共享一个 session 被两个协程同时用 | `AsyncSession` 非并发安全,一个时刻只许一个协程用 | 请求级会话(每请求一个);绝不存模块级全局(第 1 讲 + 本讲) |
